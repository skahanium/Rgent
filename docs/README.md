# 文档地图

从这里进入 Rgent 的文档。

**围栏篇**只写已经拍板的产品性格与现行合同。**施工图**写当前做到哪、下一步碰哪；**施工历史**冻结按日期的整轮记录，只描述当时，不回填、不重写。

v0.2.0 的当前阶段是 **「正文直写与审阅」**；W0 文档与合同切换已本机交付，运行时代码仍是 v0.1，W1–W7 未开。不要把目标合同读成已实现。

## 从哪读起

从决定到交付：**产品合同**在[已拍板决定](decisions.md) → **工程取舍**在[施工对象](topics.md) → **当前阶段与交接**在[施工图](build.md) → **旧阶段证据**在[施工历史](build-history.md) → **代码与测试**在仓库。

改产品性格或架构时，以[已拍板决定](decisions.md)为对照表。先改那一篇，再改其它围栏篇和代码。

编码 Agent 从仓库根目录 [AGENTS.md](../AGENTS.md) 进，不要从本文或[理念](vision.md)开写。

| [已拍板决定](decisions.md) | 原则门、v0.2 现行合同、明确未锁；旧合同保留为历史 |
| [前端协议](frontend.md) | 视觉语言、界面结构与呈现；v0.2 目标明确标注未实现 |
| [架构](architecture.md) | 已成立结构及代码强制点；v0.1 实现与 v0.2 目标分开 |
| [施工守则](handbook.md) | 动手纪律、版本升级、文档归档、门禁 |
| [开源说明](opensource.md) | MIT、贡献、治理、安全披露 |

不设独立 ADR 目录。新的重大产品决定写进 `decisions.md`；前端呈现细则在[前端协议](frontend.md)展开，不重复产品行为。

## 建议阅读顺序

人：

1. [理念与远期](vision.md)
2. [已拍板决定](decisions.md) 的 v0.2 合同
3. 当前阶段：[施工图](build.md)
4. 前端：[前端协议](frontend.md)
5. 结构：[架构](architecture.md)
6. 动手：[施工守则](handbook.md)
7. 旧证据：[施工历史](build-history.md)

编码 Agent：根目录 [AGENTS.md](../AGENTS.md) → [施工图](build.md) 当前阶段 → 相关围栏篇 → 相关代码。合同冲突以[已拍板决定](decisions.md)为准。

## 用语

| 用语 | 意思 |
|---|---|
| 库 | 用户选的那个文件夹；Markdown 文件是唯一正文真相 |
| 正文 | 当前作品，纯 Markdown；不含 prompt、AI 或账本标记 |
| 修订 | 人和 AI 对正文的变更记录；按笔记对象归属，存在于隐藏 `.rgent`，文件树不显示 |
| 账本 | 这篇笔记连续的 Agent 运行史；记录运行、工具、来源、推理与错误，不记录正文 diff |
| 运行 | 一次 Agent 任务，从发起到完成／取消／失败 |
| 结果卡 | 纯问答的单次临时结果，不形成持久聊天，可插入正文或替换选区 |
| 当前这篇 | 正在看的那个笔记 tab |
| 必须遵循 / 禁止触碰 / 可参考 | 三档权限，只挡 AI |
| 单场任务范围 | 默认只读发起篇正文与本篇账本；人另授读取、新建及跨篇结构范围，均与库权限取交集 |
| 发送批准 | 核对选定模型接收方；受本地上下文影响的外部请求另确认内容、目的地和用途 |
| 沙箱体系 | 应用授权与执行隔离共同约束任务及第三方资源；完整接线未开 |
| 技能 | 设备级技能条目，按库启用、按场冻结；不是树上笔记，也不是 MCP |
| v0.1 / v0.2 | v0.1 是已交付的块级实现；v0.2 是当前目标阶段，W0 只做文档 |
| 施工图 | [build.md](build.md)。当前阶段与依赖顺序，不是合同 |
| 施工历史 | [build-history.md](build-history.md)。冻结的历史记录 |
