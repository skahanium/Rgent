# 施工守则

动手前先读 [已拍板决定](decisions.md) 和 [施工图](build.md) 的当前阶段。工程题看 [施工对象](topics.md)。本文是纪律，不是功能清单。理念见 [vision.md](vision.md)，结构见 [architecture.md](architecture.md)。

编码 Agent 从仓库根目录 [AGENTS.md](../AGENTS.md) 进。

## 改围栏

1. 先改 `docs/decisions.md`（必要时同步 [理念](vision.md) / [前端协议](frontend.md) / [架构](architecture.md)）。
2. 再改其它围栏篇和代码。
3. 不要用实现「顺便」推翻围栏。
4. 换阶段只改 [施工图](build.md) 的「当前」和根目录 `AGENTS.md` 里那一行硬停。不改围栏，除非产品性格变了。

## 必须

- 产品是单机笔记兼资料库。新能力先问：是否服务「记笔记 / 一场 `/` / 门禁下的文件操作」。不是，就不要做。
- 先看当前阶段。未开的对象禁止实现。
- 渲染进程不直接读任意路径、不内嵌厂商 SDK、不自己连 MCP。
- 权限名单和技能文件 AI 不可写。人写盘通道（`noteWrite`）也写不了隐藏路径。
- 动到工具、数据出口或第三方进程时，先读[沙箱合同](decisions.md#沙箱与单场任务授权未来合同当前未开放)与[工程门](topics.md#沙箱与任务授权)。核对任务授权、资源代理和平台证明是否实际交付；白名单、SDK 代转、迁进程或 CI 绿灯不代替边界证据。当前未开能力只修规划，不接线。
- Host 阶段用 Electron `safeStorage` 加密密钥，密文只存应用数据目录；解密材料由操作系统保护。不要把真实密钥、库内容、权限名单样例写成真实秘密。
- 测试不把真实 API Key 写进仓库。
- 改壳、preload 或 sandbox 之后：`pnpm test` 必须过，且 `pnpm build` 后窗口能起来。sandbox 下 preload 必须是可加载的 CommonJS（`out/preload/index.cjs`）。
- 当前阶段提交前跑 `pnpm docs:check`；CI 按[变更范围分层](#ci-分层)。代码门在 macOS、Windows 上以锁文件安装，先构建与原生装载检查，再运行 `pnpm test` 与功能 `pnpm ui:check`；纯文档不触发产品构建。
- 功能走分支 + PR。GitHub 是源码枢纽。不要用未 push 的本机工作树当云端起点。

## CI 分层

工作流 `Verify` 保留分支 push、PR 和手动入口；本地编辑与未推送提交不触发 CI。分类与汇总门始终运行，不用整条工作流的路径过滤或 `[skip ci]` 绕过检查。

| 变更 | 自动检查 |
|------|----------|
| `docs/`、根目录 `AGENTS.md`／`README.md`／`CONTRIBUTING.md`／`LICENSE` | 单平台文档检查，不安装产品依赖或编译原生模块 |
| 文档检查器及其用例 | 文档检查，加既有检查器定向测试 |
| 产品代码与测试 | 双平台构建、产物／preload／原生装载、类型与测试、构建后的功能窗口 |
| 渲染层、壳、主题、窗口脚本、依赖、构建、CI 或未知路径 | 在代码门之上增加固定日夜视觉样张 |
| 废纸篓探针与两平台实验源码 | 独立双平台探针与报告；仅改实验不构建产品 |

混合变更取所需检查的并集；删除、改名同时核对旧新路径。PR 按共同祖先计算变更，push 核对推送前后全部净差异；新分支或无法取得差异时回退代码门与视觉采证，不推断为文档。工作流本身改动同样接受双平台门禁。

非默认分支的 push 若能确认同一提交已有本仓库开放 PR，则由 PR 承担完整验收，push 只保留分类与去重回执；默认分支始终验，API 失败或无法确认时正常运行。普通 job 自动取消同分支同事件的旧任务；废纸篓探针独立排队，不自动取消正在运行的实验，保留原超时与自建夹具清理约束。手动 `full` 跑全部门、`standard` 跑代码与功能窗口、`trash` 只跑文档和独立探针；阶段交付用 `full`。

`CI gate` 是始终汇总的统一状态：所需 job 失败、取消或意外跳过均不能报通过。将来设置分支保护时要求此状态，不能要求纯文档时有意跳过的矩阵 job。文档轻检查成功不代称对应提交已通过双平台产品验收；记录产品证据时继续指明实际受验的代码提交。自动视觉截图与探针绿灯仍不代替用户视觉确认或废纸篓安全证明。

## 禁止

- 把已作废的 Flutter / Pydantic / 驾驶舱重新当骨架。旧合同不是现行围栏。
- 按根目录探路脚本的写法扩散到产品代码。
- 把密钥、库内容、权限名单样例写成真实秘密。
- 把尚未拍板的摆放备忘写进**围栏篇**。已确认的前端规则见 [前端协议](frontend.md)；精确数值可在本规则内验证调整，未讨论的结构或交互仍须先问人。施工图可以写本阶段做什么，但必须标明不是合同。
- 把施工图里的实现取舍抄进围栏装成已定。
- 从 `vision.md` 开写功能。

具体禁令以 [已拍板决定](decisions.md) 为准，不要在这里再抄一份。

## 仓库骨架

产品骨架是 Electron + TypeScript，以根目录 `package.json` 为准。不要把已删除的 Python 探路件写回来，也不要按其写法扩散。产品性格以围栏篇为准。当前做什么以 [施工图](build.md) 为准。

## 文档与代码同步

行为与 `decisions.md` 冲突时，以围栏为准并开讨论。补测试、补界面时若发现围栏不够用，回到文档补未锁项或改已拍板条目。代码里已经成立的强制点，补进 [架构](architecture.md)，不要只留在注释里。

跨能力施工按「[产品决定](decisions.md) → [工程问题](topics.md) → [阶段依赖与交接](build.md#跨能力交接) → 代码证据 → 验收」留痕。依赖图说明先后，交接表指出上游实际交付的接口或行为、下游何时可用及需要的证据；功能测试、本机真实窗口、双平台 CI、用户视觉确认分别记录，不能用一种证据代替另一种。合同已经拍板但尚未到阶段的能力，只改规划与门禁，不摆放空页面或接线。设置页面随真实能力开放，最终视觉校准另做一轮。

沙箱施工的机制说明、允许的资源、反例、平台／程序版本、构建后原生验证分别记录；失败写出具体阻断并保持能力关闭。架构只收已经成立的强制点，目标数据流留在施工对象。合同冲突经用户授权裁定时，在[施工图](build.md#沙箱规划入库与冲突裁定)留痕并交付裁定摘要，不能用规划替代现有删除、保存或恢复门。

本次三项确认的替代关系见[讨论调整](build.md#三项讨论后的规划调整)：基础文件操作与废纸篓分开验收，任务读取／对外发送分开授权，远端只读 MCP 与本机可执行 MCP 分开接入。阶段完成须核对自己的全部证据；独立删除门失败不能报删除已交，也不把未开能力的未来合同读成当前施工许可。

前端施工先读 [前端协议](frontend.md)：按语义 token 与日夜参考图核验布局、文字、控件状态和键盘操作。参考图不代替文字合同；调整已拍板的结构或交互，先与用户讨论，再同步修改 `decisions.md` 与前端协议。当前阶段未开放的 UI 不因协议入库而提前施工。
