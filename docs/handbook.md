# 施工守则

动手前先读 [已拍板决定](decisions.md)。本文是纪律，不是功能清单。理念见 [vision.md](vision.md)，结构见 [architecture.md](architecture.md)。

## 改围栏

1. 先改 `docs/decisions.md`（必要时同步 [理念](vision.md) / [架构](architecture.md)）。  
2. 再改代码或界面。  
3. 不要用实现「顺便」推翻围栏。  

## 必须

- 新能力先问：Pydantic AI 或 Harness 是否已有积木。有则组合，不要平行再造。  
- 界面只通过本机接口与发动机说话，不在 Dart 里写厂商 SDK、不在窗口进程里直接改工作区文件。  
- 写文件走库的 HITL，让用户过目后再落地。  
- 路径必须落在该任务绑定的工作区根之内。  
- 密钥只读写系统凭据库；环境变量仅作覆盖。窗口负责收集，发动机负责写入凭据库。  
- 产品数据（配置、会话库及其中的检查点）只进用户选定的数据目录；系统盘只允许数据目录指针。  
- 第一次运行必须能选数据目录、能保存密钥，缺一则不要假装已经可日常使用。  
- v0 不接 Shell / 命令执行积木。  
- 同工作区同时只让一个任务写。  
- 归档须用户手动触发；不得把进行中或待确认的会话自动送进归档或删除。  
- 测试优先用 Pydantic AI 的 test model 等不消耗真实配额的方式，不为了测界面去把密钥写进仓库。  

## 禁止

- 自研与 Pydantic AI 平行的事件内核、自研 LLM HTTP 客户端、再包一层「通用 Provider 框架」。  
- 整包默认挂 `Coder()` 当产品本体。  
- 网页壳、Electron、Qt、Flet、用浏览器当正门。  
- 把 API Key、会话全文、检查点写进仓库、工作区或文档示例。  
- 把产品文件藏进工作区（包括「隐藏目录方便」）。  
- 任务历史默认上传或云同步。  
- 为预留而引入 Harness 的浏览器、云沙箱、Temporal、ACP 等 extra；要开某一个，先改 `decisions.md`。  
- 在未提供命令能力的前提下，用任意「跑一段脚本」的捷径改工作区。  
- 把未锁项（IPC 形态、库引擎、页面结构）写进代码注释当已定合同。  
- 默认把会话库建在系统盘用户目录且不提供自选数据目录。  

## 仓库里的探路文件

根目录若仍有探路脚本（例如 `hello_world.py`），不当作产品骨架，也不要按它的写法（在脚本里直接拼 `OpenAIChatModel` / `base_url`）扩散到发动机或界面。产品结构以本文档为准。

## 文档与代码同步

行为与 `decisions.md` 冲突时，以文档围栏为准并开讨论，而不是让代码成为唯一真相。补测试、补界面时若发现围栏不够用，回到文档补未锁项或改已拍板条目。
