# 已拍板决定

本文是总账。改产品性格先改这里，再改其它围栏篇和代码。施工图跟着当前阶段改，不是性格。

只收录已经点头的结论。产品性格、产品级数字和禁令以本文为准；可调整的工程默认值写在施工对象里，不升格为永久合同。

文中 **v0** 指围栏内第一代可演示客户端，不是商店版本号。

已确认的视觉语言、界面结构与交互呈现见 [前端协议](frontend.md)。本文仍负责产品行为；参考图及可调数值不能改写本文的权限、保存、AI 和检索合同。

## 1. 原则门

破了就不是这个产品。

- 第一次打开必须先选一个文件夹当库。空的也行。不选进不去。
- 文件夹不见了（改名、挪走、盘拔了），下次打开停在选库。让人重新指。不偷偷另起一个空库。
- 没配模型密钥仍是完整笔记：看、写、搜、文件树照常。只是 `/` 和模型相关能力不可用。
- 禁止触碰、必须遵循只锁 AI，不锁人。
- 人搜得到禁止触碰的笔记。模型的本地检索搜不到。
- MCP 读到的、带出的，只走应用代转的出口，并过同一套门；可执行组件自身的文件、网络和子进程访问另由执行隔离约束。每个候选须在 macOS、Windows 证明出口受控，任一平台无法证明就不接入；白名单或一次成功调用不能代替证明。
- 一场 `/` 只编辑发起时那篇笔记的正文和本篇附件。对库内其他可参考笔记，仅可在人的单场范围授权内改名、移动，或经人逐次确认后删除；不能编辑它们的正文。范围授权不能放宽三档权限。
- 回车发送口令并散场；切到另一个笔记 tab 也立刻散场。已提交的生成任务继续在原笔记运行，切 tab 不取消、不把结果写到新 tab。
- 生成任务绑定发起笔记；关掉该笔记 tab 也不取消，重开时仍能查看。每篇同一时刻最多一场运行任务，不同笔记可并行；关窗口或换库须先取消受影响任务并保存已产生的未采纳内容与中止原因。
- AI 新建一篇后，人不被拽走。已提交的生成任务继续，新笔记在库里，要看自己点开。
- 半成品技能能存，不能加载。名字、什么时候用、具体怎么做都写齐了才能加载。
- 库就是磁盘上那个文件夹。备份靠人自己。软件不另做快照，也不把库绑成 git。
- 人从文件树改名、移动或删除笔记前，软件先保存受影响的草稿并复核磁盘修订；冲突仍由人用双预览决定，不能静默覆盖。运行任务涉及该路径时先停止并保住已生成内容。笔记与同名附件夹作为同一归属单元处理。
- 人删除单篇笔记及其同名附件夹时逐次确认，送入系统废纸篓；不退化为永久删除。普通恢复须回原文件名与原目录，并保留原有权限档。无法确认恢复对象时，AI 对该路径失败关闭。
- 中断的文件操作可查看操作、相对路径、各对象进度和核验失败原因；人可以要求重新核验并续跑，不能强制完成、清空记录或覆盖目标。重试必须针对当前库会话和当前恢复记录，不使用换库前的预览或迟到结果。
- 新结构提交不得让本库其他正在生成的任务陷入恢复门禁：这些任务仍运行时，提示先停止和保存，不能擅自取消。已有中断记录重试时，受影响篇的生成内容未保存就拒绝；无关篇的内容保留在 Host 内存，核验恢复后再按原权限补存。无法补存仍保留并说明，不伪装成文件恢复失败。
- 系统废纸篓的恢复由人在 Finder／资源管理器执行，Rgent 核验原对象、内容、附件与原权限。应用删除和恢复核验单列为未开能力，安全门未过时入口关闭；人的文件操作基础与其他能力可各自验收，不要求与删除同时交付，也不能宣称完整文件生命周期已交。AI 删除仍须另过同一安全门和人的逐次确认。
- 人仍可在 Finder／资源管理器删除文件；Rgent 须识别外部消失，阻止旧 tab 或任务自动保存重新创建原路径，并使无法核验的恢复对象及相关来源对 AI 失效。此项须在文件操作基础验收，不能把系统外部删除视为应用废纸篓已交。
- 外部消失或替换后，窗口稿及 Host 未保存结果继续保留；人可预览后另存到未占用的新笔记路径。正文保留窗口稿，最后核验的账本保留，未落盘回答以原任务 ID 和状态完整追加其中。另存不重启任务、不自动采纳 AI、不复制附件或改写相对引用；成功复读核验后才解除对应未保存状态。

## 2. 产品合同

已点头。不做就会做成别的软件。

### 壳与运行时

- 壳是 Electron。v0 就要 Mac 与 Windows。
- 产品逻辑是 TypeScript。不上 Python 边车；探路用的 Python 已移除，产品骨架是 Electron + TypeScript。
- 原生代码只用于必须由操作系统强制的安全边界。现有库读写边界是受控的 Node-API 模块，承担路径收敛与原子替换，别处不再解析库内路径；未来执行隔离若不能由现有运行时实现，可增加最小的平台原生适配，但须先验证机制、签名与双平台边界。应用逻辑仍用 TypeScript，不借此引入另一套业务运行时。现有原生模块构建需要系统 C++ 工具链与 Python 3（node-gyp），Python 不作为产品边车。
- `AgentHost` + [Vercel AI SDK](https://ai-sdk.dev/) + 官方 MCP TypeScript 客户端；v0 部署位置是工程选型，见 [施工对象](topics.md#多进程--并发)。
- Harness 做实：目标 → 工具 → 观察、硬刹车、错误回喂、完成可核对。
- v0 由单个 Agent 自己选工具、组织步骤。应用提供工具、门禁、硬刹车和可核对的完成，不另做规划器或多 Agent。先做好一个可自定义的助手，多助手不被永久排除，但须另行讨论；已确定的库内人工记忆规则见下文，尚未开放。连续多轮、子代理与多代理编排也不从现有工具环推导为已开放。
- 外循环以后再说。v0 不无人值守扫库。
- 无 Shell：模型没有命令行工具。MCP 先逐项接经审定的远端 HTTPS 服务，不下载服务器代码、不向其挂载笔记库；本机可执行／stdio 服务器后置，须先通过双平台执行隔离及逐候选验收。不提供任意可执行文件、脚本或用户自填 stdio 的运行入口。协议客户端是经审定的核心依赖，不与不可信服务器程序混为一层。
- 每个生成任务必须有总时长、模型步骤和工具调用的有限上限，不能关闭硬刹车；默认值按已开放的能力分档，在设置页可修改。任务启动时固定所用配置，运行中改设置不追溯。超限或明确取消都停止后续工具，保留已产生的未采纳内容并写明原因。各档初始默认值见 [施工对象](topics.md#agent-核心框架)。

### 编辑与渲染

- CodeMirror 6 即时渲染。文档是 Markdown 字符串。
- 正文只有一条编译管线。语法用插件加。画布不另解析一套。写盘写编辑器里的 Markdown 字符串，不用 AST 倒回去冒充原文。
- 公式、图、表、wikilink、callout、嵌入做成 viewport widget，懒加载。
- v0 渲染范围：GFM + frontmatter + 公式 + callout + `[[链接]]` + 嵌入 + Mermaid。
- Callout 跟 Obsidian 常见写法走（`> [!note]` 这类）。
- 嵌入：v0 只做可点的 `[[全路径]]`，不把另一篇正文嵌进当前篇。图仍可插在文中。嵌笔记以后再说。
- `[[链接]]`：括号内写完整路径，避免重名。界面只显示文件名。例如磁盘是 `[[工作/会议纪要]]`，屏幕上是「会议纪要」。
- 用 5～10 篇含公式、图、表、双向链接的长文压滚动与输入延迟。测得的数字补进本节。
- 不为别的编辑器做兼容。
- v0 不做「一键纯源码」。
- 即时阅读时隐藏不必呈现的 Markdown 定界符；光标进入或选区跨过一个块时，该块露出原始源码供准确编辑。显示变化不得改写原文。普通单击 Markdown 与 `[[链接]]` 进入编辑，⌘／Ctrl+单击才打开。
- YAML frontmatter 在阅读时折叠为属性摘要，点入显示原始 YAML。原生 HTML 只呈现经过净化的基础排版安全子集；未支持的片段显示为不可执行源码，不执行脚本、iframe、SVG 或事件属性。
- Markdown 图片可显示库内附件及直接 HTTP/HTTPS 图片地址。人的或已采纳正文 HTTPS 图片自动加载；未采纳 AI 正文与全部账本外链图片逐张点击加载，HTTP 始终点击。无法核验的草稿来源采用点击加载。主进程核验图片来源及实际连接公网地址，每跳重定向重新核验；显式加载的图片跨目标重定向或 HTTPS 降级须再次确认。外链图片只作为图片呈现，失败时保留可读占位，不把远程内容当 HTML、脚本或模型指令；这一展示请求独立于未来的 Agent 联网总闸。

### 记录即正文

- 正文是笔记画布对应的文件内容。你写的笔记、提交给 AI 的提问口令和未采纳的 AI 回答都留在正文里；账本是同文件末尾另行分隔的讨论记录。正文可继续整理成成品稿。
- 段是块。只能拖到段落之间。拖动是搬家。
- 屏幕上两种样子：你写的，和还没采纳的 AI 块。采纳后跟手写一样。
- 每段有稳定编号。拖动只改当前顺序，不改编号。
- 点「采纳」才转正。拖只换位置，不换身份。
- 默认按段落切成多块。可以多选，一起拖、一起采纳。
- 未采纳的 AI 块不能改字。先采纳再改，或删掉再问。账本里的原文不动。
- 生成期间暂时锁住本场口令和本场未采纳 AI 块；同篇其它正文仍可编辑。人的改动与模型写入不能互相静默覆盖，有重叠或无法确认时走双预览冲突决策。
- 你的口令不是 AI 块。
- 一段有三种身份：人写的、未采纳的 AI 块、口令。身份要跨会话存活（散场后未采纳块仍留在这篇里），所以它必须能从文件本身读出来。
- 身份标记的写法（已拍板）：在被标记块的**前一行**单独放一枚整行 HTML 注释，没有闭合标记。未采纳的 AI 块用 `<!-- rgent:ai:v1 -->`，口令用 `<!-- rgent:prompt:v1 -->`。注释里可以带属性，属性位留给技能阶段标技能名。
- 标记只写在**顶层**块与块之间，不许写在段落中间（那会把一个段落劈成两段），也不写进引用、列表这类容器内部——索引只收顶层块，认了容器里的标记就是「标了却管不着」。
- 一枚标记只标它下面紧接着的那一个块。多块 AI 输出就多枚标记——每块各自采纳、各自拖动，与「段是块」一致。标记本身不是块，不进块清单。
- 写文件时标记跟正文一起落在同一个文件里；读的时候标记被消费掉，画布上把它藏起来，只留块的两种样子。
- 采纳就是把那一枚标记删掉，正文一个字都不用改；丢弃就是把标记连同它标的块一起删。所以「标记即状态、位置即顺序、删标记即采纳」，不另写编号或 ID。
- 别的编辑器会看到这些注释行；那是接受的结果——内容不丢、不脏，围栏本来也不为别的编辑器做兼容。
- 块编号不落盘。编号与顺序在每次打开时重新派生；「拖动只改当前顺序，不改编号」只在这一次打开期间成立。

### 一场 `/`

- 只从空段的段首按 `/`，就在这一段打字。选中一句或一段不会开对话。要对着它们说话，另找空段按 `/`，用话指出来。
- 回车发送口令、关闭输入态并散场，同时启动绑定在这篇笔记上的生成任务；Shift+回车换行。生成中可用 Esc 或停止按钮明确取消任务。
- 回车后，提问留在发起笔记正文的原段，成为带轻标记的口令；AI 块接在下面。口令原文另记入账本供只读回顾，不能只记账本而从正文删掉。
- 提交前先保存人的当前草稿；保存失败不启动模型，也不丢口令。生成过程及结束写回同篇文件时，按修订值串行核对；写入冲突保留窗口稿和已生成内容，交人决策。
- AI 先出现在你按 `/` 的那段下面。位置不对就拖。模型不负责选落点。
- v0 的一场就是你一句、AI 一段。下一句是账本新的一章。新回答落在你新按的那个 `/` 下面；后续多轮交互另行拍板，不能把连续聊天当作本条的默认延伸。
- 点结束或关掉输入条、点到正文别处开始自己写、切 tab，都会结束本场输入交互；已提交的生成任务继续。Esc、停止按钮或关窗才取消仍在进行的任务。
- 没有「继续问」自动咬住上一块。还要聊就再自己找段首按 `/`。
- 未采纳的 AI 块留在任务发起时那篇里。切 tab 后任务仍可被查看和明确停止；生成结束不自动接续上一场对话。
- 生成中途可用按钮或 Esc 停。已写出的段落留下，仍是未采纳 AI 块。账本记「已中止」和当时那些字。

### 账本

- 应用内只读。按次按日期分场；外部编辑器仍可修改同文件，账本不承诺防篡改。
- 写在这篇笔记同一个文件里。文件树里不出现，不能当一篇笔记点开改。正文画布里也没有编辑位。
- 入口始终位于当前笔记正文画布右上角。点开后在同一笔记 tab 内临时显示只读账本，关闭后回到原正文位置；不新增 tab，不占右侧反链。
- 回顾按正文同一 Markdown 管线安全呈现，仍不可编辑、不可进入正文索引或人搜。
- 你对 AI 说的话会留在正文里（你的样式，能改能删，有很轻的标记）。若注入了技能，口令上还要明显标出技能名。
- 账本保留口令原文供应用内只读回顾，并记技能名。删正文口令不会擦账本。
- 每一章记：口令、AI 当时全文、一句很短的工具摘要。
- 每一章可核对地记录任务身份、时间、结束状态和中止原因；一次任务不能因重试追加多章。Host 最小环没有工具时工具摘要如实记为无工具。
- 不记思维链。不记事后会过期的位置地图。
- 内部思维链不进笔记。跑时可展开看，任务结束丢掉。不另做缓存库。
- 账本写在同一文件的最末尾，用一行机器锚点 `<!-- rgent:ledger:v1 -->` 与正文分开。正文永远在锚点之前；锚点之后只属于账本。
- 正文在前，编译出的位置因此不需要位移；纯文本编辑器与 git diff 看到的是「你的文章 + 一段追记」。
- 索引一律只吃锚点之前的正文：人搜、反链与将来的模型检索都不得索引账本。组模型上下文时，账本另按「喂给模型」的规则读取，不混进正文或检索语料。
- 锚点行是选定值，不是永久合同（带 `v1` 以便日后能检测而不是误读）。库里目前没有任何账本，改锚点等于一处常量加一次扫描迁移。

### 喂给模型

- v0 每次都分别提供两类带标签的来源：正文（尽量全文；块编号 + 当前顺序 + 身份）与本篇账本。磁盘上的正文和完整账本是事实来源；进入模型的旧账本章节在超限时可用带来源指示的临时摘要代替，摘要不落盘、不改写账本，也不能当作原文证据。
- 另带这一次 `/` 点在哪两块之间。
- 组上下文须为模型输出和工具结果预留空间。正文、账本及本次任务所需内容合计放不下时，优先保住当前口令、落点附近、文首及尽量多的正文；旧账本章节先压缩，仍超限才截断正文中间。文首与落点附近各占多少字未锁。
- 临时摘要只在本次生成任务内使用，标出所依据的账本章节；摘要和账本都是低信任内容，不能提升为系统指令。需要精确引用旧话时须回到可用原文核对；无法核对就说明不确定，不得补造。
- 相邻两段不等于相邻两轮对话。
- 口令在正文和账本里都会出现。稿是什么听正文。

### 库、文件、窗口

- 文件夹里已有的 Markdown 都是笔记。其它文件能在树里看见，但不按笔记打开。
- 每篇笔记自己带一个附件小文件夹，名字就是笔记名（`工作/会议纪要.md` 配 `工作/会议纪要/`）。图和 PDF 放这只夹里；插入附件时才建夹，不给空笔记预先建空夹。
- 引用写全路径：`![](会议纪要/pic.png)`、`![[工作/会议纪要/pic.png]]`。解析仍按 Markdown 标准相对路径走，软件不额外去同名夹里猜——这样同一份文件在别的编辑器里也显示得对。
- 文件名跟标题走。「会议纪要」就是 `会议纪要.md`，附件夹同名。不能当文件名的符号由软件替换。改标题就改文件名，附件夹一起改，库内 `[[全路径]]` 也尽量一起改掉。
- 人手动改名或移动时，先预览可能变化的 `[[全路径]]` 引用；只有确认后才逐篇按修订值修复，失败必须列出未修复项。AI 对其他笔记的结构操作不得借此改写那些笔记的正文。
- 平时自动写盘，也可随时手动保存立刻再写一次。不是纯手动。
- 并发替换只承诺两件事：不写出库外（判不出来就失败关闭）；到修订值核对点为止的外部改动能被发现并报成冲突。核对点之后、提交之前若目标被外部换掉，属已知残余窗口——两平台同一口径，没有可移植原语能表达「仅当目标仍是预期文件身份时才替换」，所以不承诺比这更强。**这个残余窗口是不报冲突、也不弹窗的**：下文「问你听谁的」只对已经发现的冲突成立，别把它读成残余窗口也交给人。
- 窗口里的稿和磁盘上这份文件不一样了，同时给出窗口稿与磁盘稿的两份预览，让人看清差异再问听谁的，不默默盖掉。**这句只管已发现的冲突**（见上一条的残余窗口）。
- 退出时保存失败，不得静默丢稿，也不得把应用锁在无法正常退出的状态；人能继续编辑、重试保存，或明确选择放弃未保存修改并退出。
- 可以开多个笔记 tab。正在看的那篇才是「当前这篇」。
- v0 不拆成两个窗。写字边界跟着当前 tab。
- 左边文件夹树可收起，默认收着。右边反链常驻。要翻目录再拉出左边。
- v0 要有反链。打开一篇能看到谁链到了它，按文件夹分组，点文件名跳转。呈现要组织得好看，不糙。
- v0 不做应用内历史版本。

### 权限

- 三档：必须遵循、禁止触碰、可参考。未标明的路径默认可参考。
- 必须遵循只锁 AI：人能改这些笔记；模型不能写，`/` 只提示只读。
- 禁止触碰只挡 AI：人能打开、能搜到；不进模型检索，`/` 碰不到。
- 一份路径名单。设置界面改，真正写在库里隐藏文件。换机器、进 Git 跟着库走。
- 文件树里对文件夹右键设档。设置页有一张总表。
- 树上只给「禁止」和「必须遵循」打标。默认可参考不挂徽章。
- 权限名单模型不能改。规则文件 AI 不可写。人写盘通道也写不了这份文件。
- 对文件夹设档后，其下未另标的路径跟这档走。更长路径的条目覆盖更短的。
- 对一篇笔记设档时，同名附件夹（`会议纪要.md` 配 `会议纪要/`）及其下未另标的路径跟这档走。附件夹上若另有更长条目，以那条为准。笔记不因附件夹被设档而自动改档。
- 同一实际文件或目录的权限不能因路径大小写、Unicode 规范形式或并发替换路径而变弱；主进程无法确认路径与名单条目的对应关系时，AI 出口失败关闭。

### 检索与联网

- 不靠人在哪个文件夹里机械分类。专业问题由模型判断是否先搜本地、不够再上网。
- 「必须按原文」在提示里写死：涉及就查，回答要对着原文。
- 写盘仍不听模型：禁区碰不到，必须遵循的原文不能改。软件可抽查是否真的检索、引用。
- 人：v0 就能搜标题，也能搜正文句子。人搜得到禁止触碰；检索引擎是 v0 工程选型，见 [施工对象](topics.md#手动检索)。
- 模型检索不含禁止触碰，且只返回本场读取范围内的结果与路径信息。与人搜同一份全量语料，查询期同时过滤任务范围与有效权限，禁止建索引时把禁区抹掉做成唯一一份「看不见」的索引。人搜仍不受任务范围限制。
- 模型检索的方法不与人搜子串绑定。搜库工具返回带路径的可引用片段；倒排、BM25、按块切等未锁。向量检索不做。Host 最小环不提供搜库工具。
- 有应用级联网总闸：开仅表示允许提出搜索、抓页或 MCP 请求，不替代本场数据发送授权；关了关闭这些出口。总闸不关闭发起 `/` 所需的已配置模型文本接口，也不控制笔记图片展示；各用途分别授权和核验。
- 初期，受本地上下文影响的搜索、抓页与 MCP 请求，发送前展示实际内容、目的地和用途，经人确认才发出。读取笔记或允许送入选定模型不等于允许再送给搜索服务或 MCP；模型改写的问题、摘要和记忆也受此约束。不能证明请求只使用已批准的发送材料时须确认，不用关键词过滤推断“通用／不敏感”。同内容、同目的地、同用途的已批准请求可按有限重试规则重发；内容、目的地或用途改变须重新核验并确认。
- 禁止触碰的内容不经应用代转带出（模型上下文、应用发起的搜索与抓页、经主进程转发的 MCP 调用）。MCP 也不例外。无法代转的服务器不准接。必须遵循的原文只在有效读取和发送授权内使用，优先最少必要摘录；人的发送确认不能放宽禁止触碰或来源失效的限制。
- 抓回的网页进模型只准纯文本或 Markdown 摘录，当不可信输入，不得当系统提示。抽正文用哪套库、超时、体积上限未锁。
- 联网总闸独立于设置主入口。

### 沙箱与单场任务授权（合同与开放边界）

- 沙箱是 Host 执行请求与资源操作之间的基础安全体系，同时防范模型误操作和第三方组件直接越权。应用授权决定操作是否获准，执行隔离限制组件能直接接触的资源；两层都须有可核对的强制点。现有 renderer sandbox、固定库根 IO 和无工具 Host 不代表完整 Agent 沙箱已经交付。
- 有效权限取应用已开放能力、库内三档权限、单场任务范围、工具限制及当前对象状态的交集。未开放的能力默认拒绝；未标记路径默认可参考的原规则保留。人可通过独立入口读写禁区，模型和第三方组件不能借用人的通道。
- 单场读取默认限发起篇正文及本篇账本。人可为本场明确授权其他笔记或目录；模型可请求扩展，但不能自己批准。读库／搜库只在该范围与当前三档权限的交集内工作，跨篇结构授权不隐含读取权。展示读取范围时同时说明内容会进入本场选定模型端点；云端模型即对应供应商接收，单场更换模型端点也须让人核对接收方。本轮施工先把既有最小环接入范围与模型接收方确认，验收后才开放两项只读工具。
- 读取、向选定模型发送、向搜索／MCP 等外部服务发送分别受控。写入既有正文固定为发起篇及本篇附件；库内新建须明确授权目标范围，不能借新建覆盖另一篇已有正文。范围确认不放宽有效库权限，也不隐含结构操作或对外发送授权。
- 跨篇改名、移动默认没有授权。人可在任务开始时圈定范围，或在模型提出操作后看过对象、目标和影响的预览再授权；本场任务可在指定范围内连续执行，无须每项重复授权。来源、目标位置及同名附件须在授权覆盖内，目录操作核验整个受影响子树；范围扩展必须由人重新确认。删除仍须逐次确认，且受系统废纸篓安全门约束，范围授权不能替代它。
- 授权绑定当前库会话、任务和对象身份，不按裸路径字符串继承。每次操作仍复核有效权限、身份、内容修订、目标和预览；合法保存／移动只有经受信任服务核验后才能续接对象绑定，不能扩大原授权范围或正文写入权。换库、任务结束或取消后授权失效，权限收紧即时影响下一次使用，外部替换的新对象不能继承旧授权。任务配置快照不冻结权限；范围内出现变化也不能省略重新核验。
- 文件、网络和凭据操作经受信任的资源服务；模型与第三方组件没有通用读盘、直接联网、读取密钥或更改门禁的入口。模型 API、Agent 搜索／抓页、MCP 与图片展示各核对用途、目的地和允许发送的数据。密钥按连接留在受信任服务，只用于指定服务的必要认证，不作为模型内容或本机服务器环境变量，不跨连接串用。
- 笔记、账本、记忆、技能、网页和 MCP 结果均不能增加授权；助手人格与习惯也不改变能力边界。摘要和工具结果须保留来源约束，每次发送前复核，来源失效后不能继续借副本向模型或外部服务发送内容。已获准发出的请求不能承诺追回；发现撤销或来源失效时停止后续调用，尝试中止在途请求，不能把旧上下文继续当作有效依据。
- 可执行第三方组件在接入前须验证文件、网络、进程创建及必要资源上限；取消、崩溃和超限后停止后续操作，保留已产生内容与可核对结果。无法证明隔离时保持能力关闭，不降级为高权限执行。具体平台机制、限额和授权控件仍须工程验证。
- 沙箱不替代库根、对象身份、修订值、冲突及中断恢复边界，不改变既有文件操作的残余竞态承诺，也不提供历史快照或自动回滚。它约束 Rgent 启动的组件及应用出口，不承诺约束同机管理员、内核或已获准接收数据的远端服务内部行为；无法在此边界内控制的 MCP 能力不接入。

工程方案与验收见 [施工对象 · 沙箱与任务授权](topics.md#沙箱与任务授权)，前置依赖见 [施工图交接表](build.md#跨能力交接)。本节的分包开放以施工图为准；当前只先开放单场授权接入，MCP、通用联网、写工具及新设置页仍未开。

### 单场授权与首批只读工具

- `/` 口令旁浮层展示发起篇、固定参考范围、模型及实际接口主机，并说明资料会发送给该接收方。回车确认并发送、Shift＋回车换行；输入法组合不发送，取消准备保留口令。提交前排空人的草稿，预览失效或配置／来源改变须重新展示并确认。
- 默认仅发起篇正文及本篇账本；额外笔记／目录展开为固定 Markdown 对象集合，新增成员不继承授权，其他篇账本、附件、隐藏与非 Markdown 对象不开放。来源失效停止整场后续调用并保留已有结果，不自动恢复。
- 首批仅「读库」「搜库」：按授权范围先限定对象，再匹配／排序／分页；不调用人的全库搜索后过滤。返回可核对的来源和省略／续读信息，不无界铺送全文。默认范围沿用无工具档，额外参考采用本地档及设备上限快照；模型、摘要、工具尝试及失败重试共用单场预算。
- 模型单步返回文本及工具请求，Host 校验名称／参数并依序执行；SDK 不自动执行或隐藏循环。协议不支持时显错，不切供应商、不改为隐式全量发送。工具原文及参数不铺进正文，不输出思维链。
- v1 任务章追加版本化机器来源依赖，记录实际模型、授权概况、工具摘要、实际读取／发送的来源及中止原因；不存密钥或重复外篇全文，不改旧章字节。历史外篇依赖在后续入模／摘要前重新核对本场范围、身份、权限和内容；无法核验则省略并说明。旧无工具章节保持兼容，损坏新记录不得降级成无依赖。
- 授权仅内存、单场有效且一次性绑定；取消、超限、换库和结束撤销后续读／发送。可信收尾只保存已产生文字及同篇账本，仍核最新权限与对象；失败保留待保存内容。它不等于完整 Agent 沙箱或第三方执行隔离。

### 模型

- v0 就能换厂家，也能填兼容 OpenAI 的接口地址。
- 预置 DeepSeek 和 MiniMax。
- 模型设置按设备保存；预置之外的兼容接口地址只接受 HTTPS，或指向本机回环地址的 HTTP。带密钥的模型请求不跟随重定向。自定义模型需填写上下文窗口容量；模型配置与运行上限在每场任务启动时固定，运行中修改只影响新任务。
- v0 用 Electron `safeStorage` 加密密钥，密文只存应用数据目录，不进笔记文件夹或仓库；解密材料由操作系统保护。发行前分别验证 macOS 签名后读取与 Windows DPAPI 行为。
- 不可加密或解密失败时明确报错，不退回明文。界面只显示密钥保存状态，允许替换、删除；切换供应商不把上一家的密钥发送给下一家。
- 本机模型（Ollama 等）不进 v0。
- 不配密钥也能用笔记。配了才有 `/`。

### 助手、记忆与连接（未来合同，当前未开放）

- 先提供**一个可自定义助手**。通用称呼、语气和回答习惯按设备保存，所有笔记库共用；它们不赋予助手越过笔记权限或后台扫库的能力。多助手保留为以后讨论的可能，不预设身份切换或自动编排。
- 长期记忆只由人从**当前库的笔记正文或本篇账本**明确选择「记住」。保存前展示拟记内容及可核对的来源，允许人修改后确认；助手不能自行把对话、回答或摘要写成长期记忆。记录放在该库受控的隐藏位置，不混进正文或账本，也不跨库共享。
- 人可查看每条记忆的内容和来源并删除。来源内容改变、删除或权限收紧时，记忆暂停供模型使用；只有来源重新核对并经人确认，才能恢复。来源改名或移动须按对象身份核验后更新归属，不能只改旧路径字符串。无法确认来源或权限时失败关闭。
- 每场笔记内 `/` 以后可以从**同库**选取相关且仍获准使用的记忆，使用前重核来源、权限、内容和本场读取范围；选择记忆时明确展示相应来源及接收的模型端点，不能借记忆隐含读取范围外的正文或账本。实际进入该任务上下文的记忆项须可核对地记录。记忆不能绕过上下文预算、对外发送授权和低信任输入边界。自动提取记忆另行讨论，当前不做。
- 多个供应商连接可并存，每个连接的密钥独立加密和读取，不把一个连接的密钥发给另一个。设备有默认模型，发起单场任务时可临时选择其他已配置模型；启动时固定连接、模型、端点、密钥归属和运行上限的快照，运行中修改只影响新任务。失败不得静默切换到另一供应商。先交付多连接与隔离，再逐种验证新协议；OAuth、Coding Plan、本地模型等均不因参考产品截图自动开放。

### 技能

- 技能是 prompt 说明文。不是文件树里的文档，也不是 MCP。
- 人只能在设置里技能这一页打开编辑。
- 磁盘上跟库走，对文件树隐藏。文件树里没有技能文件。
- 做好不等于能用。必须有加载、卸载。只有人点加载、卸载。没写完也能先存着。名字、什么时候用、具体怎么做都写齐了才能加载。
- 没加载的只待在技能库，不进 `/` 候选栏。卸载后文件还在。模型不能自己上架。
- 生成技能两条路：
  1. 设置里点「制作技能」，按内置模板手写，产出未加载技能文件。
  2. 在可写笔记里用 `/` 把需求谈清楚，浮栏里用内置「生成技能」。先确认会新建一份未加载技能、这篇笔记不删不收走。点头后另外新建一份完全按内置模板填好的技能文件，未加载、树上看不见。原笔记原样留着，文件树不动。
- 新建后立刻打开设置里技能这一页这份未加载技能，由人检查再决定加不加载。
- 制作过程留在原来那篇笔记里，不进技能。
- 技能按软件内置模板把事说清楚。人不改这份模板。就地收走、删笔记、账本进技能包均作废。
- 禁止触碰的笔记不能拿来生成（正文不送模型）。必须遵循里 v0 的 `/` 仍只提示去可写笔记，不在这篇里生成。
- 「生成技能」是内置动作，不是某个已加载技能。
- 技能只在设置的技能页里删。卸载只是不用，删除才从库里拿走。
- 一按 `/` 立刻浮出已加载技能的全量可滚动候选栏。一次只能绑一个。打字或空格即放弃注入。
- 口令上必须明显标出技能名。

### 工具

- 库内文件工具的规划清单七件：读库、搜库、建、补任务发起篇、改名、挪、删（删须人确认）。「写稿」是建 / 补 / 改名 / 挪 / 删五件的合称，不要求五件同时交付；删除独立过安全门，未验收时不注册该工具。库内工具清单只此一份，其它篇不要再列。受控联网和逐项审定的 MCP 是外部能力，不据此新增任意库内操作或承诺固定的外部工具总数。
- 设置里只可接逐项审定且通过 [沙箱接入门](#沙箱与单场任务授权合同与开放边界) 的 MCP 白名单服务器。不接也能用；任一平台无法证明文件和网络出口受控就不接入。关闸或无法代转则不准接。
- 技能是说明文，MCP 是手。两套不能混成一种。模型不能自己接上 MCP。
- MCP 首批只审定远端 HTTPS 的只读查询、资料获取。每项写清工具、发送材料、目的地、凭据、结果来源、超时／取消与部分失败；返回值和动态发现的工具均不自动获得权限。外部写入、发送消息、发布及账号修改另行讨论并验证，不能借“只读连接”开放。本机可执行 MCP 保留为后续能力，隔离门未过时不普通启动补位。
- 生成任务只编辑发起时那篇笔记的正文和本篇附件；可在 [单场授权范围](#沙箱与单场任务授权合同与开放边界) 内对其他可参考笔记改名、移动，或经人逐次确认后删除，但不能编辑它们的正文；可移动受影响内容全部可参考且在授权内的文件夹。不提供递归删除文件夹。删除单篇笔记及其附件须逐次由人在弹窗点头。
- 工具执行前逐项检查来源、目标与受影响子树，不能靠改名或移动改变禁区的实际保护范围。库内容、网页和 MCP 返回值一律作为低信任数据进入模型上下文。
- 人工结构操作可连同对象迁移显式权限规则；中途失败或规则冲突不能让实际保护范围变弱。AI 结构工具仍待文件生命周期基础能力交付后接线。
- 要改另一篇的字，得先打开那篇再发起新的 `/`；切 tab 不改变已提交任务的目标笔记。
- 必须遵循不能改字。禁止触碰碰不到。不是后台扫库。

### 设置里有什么

- 一个设置界面，未来按工作对象分组：工作区「通用、界面」，Agent 的助手行为、库内记忆、模型与运行、权限，连接与扩展，以及应用信息。具体未交付页面的名称与控件仍待施工前确定。技能不单独再做一个面板；只显示已经可用的页面，当前为「界面、模型、运行」。页面增多后再开放设置搜索。
- 设置入口固定在左侧边栏底部，不随文件树滚动；边栏收起时仍有图标入口。设置主页面及所有层级的子页面，沿用 [前端协议](frontend.md) 的工作区视觉语言；整个设置面板悬浮在正常工作区上方且面积更小。浅色主题里侧栏与内容画布都采用浅色。打开设置时工作区柔焦并压暗，面板保持清晰；点击面板外或按 Esc 关闭并返回原焦点。当前另开放「模型」「运行」页的必要控件；其余设置子页仍待逐项讨论。
- 主题与阅读排版偏好只保存在本设备应用数据目录，重启及换库后沿用，不写进笔记库。跟随系统时响应系统外观变化；选定日间或夜间后不随系统变化。正文与标题字体分别从精选方案选择；正文字号、行距、最大阅读宽度在设置样张内先预览，确认保存后应用到本设备全部笔记，放弃未保存的调节则不改变工作区或 Markdown 原文。未来画布顶部篇名沿用标题字体；显示并直接改名另行施工，须连同附件夹、引用、tab 与 Host 任务一起验收。
- 已点名会进设置的至少有：库路径、一个助手的设备通用习惯、当前库的记忆查看与删除、多连接供应商及密钥、模型默认值、Agent 运行上限、权限总表、技能（制作、编辑、加载卸载、删除）、MCP 连接。单场模型临时选择属于发起任务的交互，不靠设置页替代；运行上限不能设成无限制或绕过门禁。

## 3. 明确未锁

下列不要写成已经定案：

- 主题的精确 token 数值及额外主题；日间／夜间／跟随系统的切换方式已定，见 [前端协议](frontend.md)
- 图谱
- 日记模板
- 除「界面」「模型」「运行」页当前必要控件之外的设置子页控件排列、面板像素；悬浮形态已定
- 底栏控件的精确间距；分隔线和联网状态点已定
- Windows / macOS 最低系统版本
- 安装包、签名、商店分发
- 第 2 节压测测得的延迟数字（测完再写入）
- 超限截断时文首与落点附近各占的字数（测完再写入）
- 权限名单文件的条目格式
- 身份标记注释里技能属性用什么键名（写法本身已在 §记录即正文 拍板）
- 模型本地检索的倒排 / BM25 / 按块切等实现
- 搜索引擎、抽网页正文用的库、超时与体积上限
- MCP 可接服务器的具体白名单与配置像素
- 沙箱的平台机制与最小原生适配、签名／分发方案、资源限额、任务授权控件及令牌格式；保护目标、范围授权、权限交集及双平台接入门已定
- 运行上限更细的单工具超时值；「运行」页采用有限正整数输入，无工具档的工具调用数固定为零
- 后续连续多轮的交互、自动提取记忆、记忆召回排序和失效后的人工复核细节、子代理权限模型、多助手与多代理编排方式；人工记忆的库隔离、来源与删除原则已定
- 新供应商协议逐种接入的认证细节、可信用量统计口径与模型分工；多连接密钥隔离和单场快照原则已定
- Host 的具体 token 预留量、摘要算法与模型上下文窗口识别方式

未锁项要落成围栏时，先改本文再施工。已确认的前端规则可按 [前端协议](frontend.md) 实施；未确认的控件细节仍须讨论，不从参考图推导。
