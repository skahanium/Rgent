# 已拍板决定

本文是总账。改产品性格先改这里，再改其它围栏篇和代码。施工图跟着当前阶段改，不是性格。

只收录已经点头的结论。产品性格、产品级数字和禁令以本文为准；可调整的工程默认值写在施工对象里，不升格为永久合同。

文中 **v0** 指围栏内第一代可演示客户端，不是商店版本号。

已确认的视觉语言、界面结构与交互呈现见 [前端协议](frontend.md)。本文仍负责产品行为；参考图及可调数值不能改写本文的权限、保存、AI 和检索合同。

## 1. 原则门

破了就不是这个产品。

- 第一次打开必须先选一个文件夹当库。空的也行。不选进不去。
- 文件夹不见了（改名、挪走、盘拔了），下次打开停在选库。让人重新指。不偷偷另起一个空库。
- 没配模型密钥仍是完整笔记：看、写、搜、文件树照常。只是 `/` 和模型相关能力不可用。
- 禁止触碰、必须遵循只锁 AI，不锁人。
- 人搜得到禁止触碰的笔记。模型的本地检索搜不到。
- MCP 读到的、带出的，只走应用代转的出口，并过同一套门；可执行组件自身的文件、网络和子进程访问另由执行隔离约束。每个候选须在 macOS、Windows 证明出口受控，任一平台无法证明就不接入；白名单或一次成功调用不能代替证明。
- 一场 `/` 只编辑发起时那篇笔记的正文和本篇附件。对库内其他可参考笔记，仅可在人的单场范围授权内改名、移动，或经人逐次确认后删除；不能编辑它们的正文。范围授权不能放宽三档权限。
- 回车发送口令并散场；切到另一个笔记 tab 也立刻散场。已提交的生成任务继续在原笔记运行，切 tab 不取消、不把结果写到新 tab。
- 生成任务绑定发起笔记；关掉该笔记 tab 也不取消，重开时仍能查看。每篇同一时刻最多一场运行任务，不同笔记可并行；关窗口或换库须先取消受影响任务并保存已产生的未采纳内容与中止原因。
- AI 新建一篇后，人不被拽走。已提交的生成任务继续，新笔记在库里，要看自己点开。
- 半成品技能能存，不能加载。名字、什么时候用、具体怎么做都写齐了才能加载。
- 库就是磁盘上那个文件夹。备份靠人自己。软件不另做快照，也不把库绑成 git。
- 人从文件树改名、移动或删除笔记前，软件先保存受影响的草稿并复核磁盘修订；冲突仍由人用双预览决定，不能静默覆盖。运行任务涉及该路径时先停止并保住已生成内容。笔记与同名附件夹作为同一归属单元处理。
- 人删除单篇笔记及其同名附件夹时逐次确认，送入系统废纸篓；不退化为永久删除。普通恢复须回原文件名与原目录，并保留原有权限档。无法确认恢复对象时，AI 对该路径失败关闭。
- 中断的文件操作可查看操作、相对路径、各对象进度和核验失败原因；人可以要求重新核验并续跑，不能强制完成、清空记录或覆盖目标。重试必须针对当前库会话和当前恢复记录，不使用换库前的预览或迟到结果。
- 新结构提交不得让本库其他正在生成的任务陷入恢复门禁：这些任务仍运行时，提示先停止和保存，不能擅自取消。已有中断记录重试时，受影响篇的生成内容未保存就拒绝；无关篇的内容保留在 Host 内存，核验恢复后再按原权限补存。无法补存仍保留并说明，不伪装成文件恢复失败。
- 系统废纸篓的恢复由人在 Finder／资源管理器执行，Rgent 核验原对象、内容、附件与原权限。应用删除和恢复核验单列为未开能力，安全门未过时入口关闭；人的文件操作基础与其他能力可各自验收，不要求与删除同时交付，也不能宣称完整文件生命周期已交。AI 删除仍须另过同一安全门和人的逐次确认。
- 人仍可在 Finder／资源管理器删除文件；Rgent 须识别外部消失，阻止旧 tab 或任务自动保存重新创建原路径，并使无法核验的恢复对象及相关来源对 AI 失效。此项须在文件操作基础验收，不能把系统外部删除视为应用废纸篓已交。
- 外部消失或替换后，窗口稿及 Host 未保存结果继续保留；人可预览后另存到未占用的新笔记路径。正文保留窗口稿，最后核验的账本保留，未落盘回答以原任务 ID 和状态完整追加其中。另存不重启任务、不自动采纳 AI、不复制附件或改写相对引用；成功复读核验后才解除对应未保存状态。

## 2. 产品合同

已点头。不做就会做成别的软件。

### 壳与运行时

- 壳是 Electron。v0 就要 Mac 与 Windows。
- 产品逻辑是 TypeScript。不上 Python 边车；探路用的 Python 已移除，产品骨架是 Electron + TypeScript。
- 原生代码只用于必须由操作系统强制的安全边界。现有库读写边界是受控的 Node-API 模块，承担路径收敛与原子替换，别处不再解析库内路径；未来执行隔离若不能由现有运行时实现，可增加最小的平台原生适配，但须先验证机制、签名与双平台边界。应用逻辑仍用 TypeScript，不借此引入另一套业务运行时。现有原生模块构建需要系统 C++ 工具链与 Python 3（node-gyp），Python 不作为产品边车。
- `AgentHost` + [Vercel AI SDK](https://ai-sdk.dev/) + 官方 MCP TypeScript 客户端；v0 部署位置是工程选型，见 [施工对象](topics.md#多进程--并发)。
- Harness 做实：目标 → 工具 → 观察、硬刹车、错误回喂、完成可核对。
- v0 由单个 Agent 自己选工具、组织步骤。应用提供工具、门禁、硬刹车和可核对的完成，不另做规划器或多 Agent。先做好一个可自定义的助手，多助手不被永久排除，但须另行讨论；已批准的库内记忆合同见下文，运行时已获施工授权，交付证据见施工图。连续多轮、子代理与多代理编排也不从现有工具环推导为已开放。
- 外循环以后再说。v0 不无人值守扫库。
- 无 Shell：模型没有命令行工具。MCP 先逐项接经审定的远端 HTTPS 服务，不下载服务器代码、不向其挂载笔记库；本机可执行／stdio 服务器后置，须先通过双平台执行隔离及逐候选验收。不提供任意可执行文件、脚本或用户自填 stdio 的运行入口。协议客户端是经审定的核心依赖，不与不可信服务器程序混为一层。
- 每个生成任务必须有总时长、模型步骤和工具调用的有限上限，不能关闭硬刹车；默认值按已开放的能力分档，在设置页可修改。任务启动时固定所用配置，运行中改设置不追溯。超限或明确取消都停止后续工具，保留已产生的未采纳内容并写明原因。各档初始默认值见 [施工对象](topics.md#agent-核心框架)。

### 编辑与渲染

- CodeMirror 6 即时渲染。文档是 Markdown 字符串。
- 正文只有一条编译管线。语法用插件加。画布不另解析一套。写盘写编辑器里的 Markdown 字符串，不用 AST 倒回去冒充原文。
- 公式、图、表、wikilink、callout、嵌入做成 viewport widget，懒加载。
- v0 渲染范围：GFM + frontmatter + 公式 + callout + `[[链接]]` + 嵌入 + Mermaid。
- Callout 跟 Obsidian 常见写法走（`> [!note]` 这类）。
- 嵌入：v0 只做可点的 `[[全路径]]`，不把另一篇正文嵌进当前篇。图仍可插在文中。嵌笔记以后再说。
- `[[链接]]`：括号内写完整路径，避免重名。界面只显示文件名。例如磁盘是 `[[工作/会议纪要]]`，屏幕上是「会议纪要」。
- 用 5～10 篇含公式、图、表、双向链接的长文压滚动与输入延迟。测得的数字补进本节。
- 不为别的编辑器做兼容。
- v0 不做「一键纯源码」。
- 即时阅读时隐藏不必呈现的 Markdown 定界符；光标进入或选区跨过一个块时，该块露出原始源码供准确编辑。显示变化不得改写原文。普通单击 Markdown 与 `[[链接]]` 进入编辑，⌘／Ctrl+单击才打开。
- YAML frontmatter 在阅读时折叠为属性摘要，点入显示原始 YAML。原生 HTML 只呈现经过净化的基础排版安全子集；未支持的片段显示为不可执行源码，不执行脚本、iframe、SVG 或事件属性。
- Markdown 图片可显示库内附件及直接 HTTP/HTTPS 图片地址。人的或已采纳正文 HTTPS 图片自动加载；未采纳 AI 正文与全部账本外链图片逐张点击加载，HTTP 始终点击。无法核验的草稿来源采用点击加载。主进程核验图片来源及实际连接公网地址，每跳重定向重新核验；显式加载的图片跨目标重定向或 HTTPS 降级须再次确认。外链图片只作为图片呈现，失败时保留可读占位，不把远程内容当 HTML、脚本或模型指令；这一展示请求独立于未来的 Agent 联网总闸。

### 记录即正文

- 正文是笔记画布对应的文件内容。你写的笔记、提交给 AI 的提问口令和未采纳的 AI 回答都留在正文里；账本是库内隐藏目录中独立保存的任务记录，正文末尾的旧记录仅作迁移历史。正文可继续整理成成品稿。
- 段是块。只能拖到段落之间。拖动是搬家。
- 屏幕上两种样子：你写的，和还没采纳的 AI 块。采纳后跟手写一样。
- 每段有稳定编号。拖动只改当前顺序，不改编号。
- 点「采纳」才转正。拖只换位置，不换身份。
- 默认按段落切成多块。可以多选，一起拖、一起采纳。
- 未采纳的 AI 块不能改字。先采纳再改，或删掉再问。账本里的原文不动。
- 生成期间暂时锁住本场口令和本场未采纳 AI 块；同篇其它正文仍可编辑。人的改动与模型写入不能互相静默覆盖，有重叠或无法确认时走双预览冲突决策。
- 你的口令不是 AI 块。
- 一段有三种身份：人写的、未采纳的 AI 块、口令。身份要跨会话存活（散场后未采纳块仍留在这篇里），所以它必须能从文件本身读出来。
- 身份标记的写法（已拍板）：在被标记块的**前一行**单独放一枚整行 HTML 注释，没有闭合标记。未采纳的 AI 块用 `<!-- rgent:ai:v1 -->`，口令用 `<!-- rgent:prompt:v1 -->`。注释里可以带属性，属性位留给技能阶段标技能名。
- 标记只写在**顶层**块与块之间，不许写在段落中间（那会把一个段落劈成两段），也不写进引用、列表这类容器内部——索引只收顶层块，认了容器里的标记就是「标了却管不着」。
- 一枚标记只标它下面紧接着的那一个块。多块 AI 输出就多枚标记——每块各自采纳、各自拖动，与「段是块」一致。标记本身不是块，不进块清单。
- 写文件时标记跟正文一起落在同一个文件里；读的时候标记被消费掉，画布上把它藏起来，只留块的两种样子。
- 采纳就是把那一枚标记删掉，正文一个字都不用改；丢弃就是把标记连同它标的块一起删。所以「标记即状态、位置即顺序、删标记即采纳」，不另写编号或 ID。
- 别的编辑器会看到这些注释行；那是接受的结果——内容不丢、不脏，围栏本来也不为别的编辑器做兼容。
- 块编号不落盘。编号与顺序在每次打开时重新派生；「拖动只改当前顺序，不改编号」只在这一次打开期间成立。

### 一场 `/`

- 只从空段的段首按 `/`，就在这一段打字。选中一句或一段不会开对话。要对着它们说话，另找空段按 `/`，用话指出来。
- 第一次回车准备口令旁授权预览；核对范围、模型与接收方后再回车确认发送，输入态结束并启动绑定本篇的任务。Shift+回车换行，输入法组合期间回车／Esc 留给候选操作。生成中可用 Esc 或停止按钮明确取消任务。
- 回车后，提问留在发起笔记正文的原段，成为带轻标记的口令；AI 块接在下面。口令原文另记入账本供只读回顾，不能只记账本而从正文删掉。
- 提交前先保存人的当前草稿；保存失败不启动模型，也不丢口令。生成过程及结束写回同篇文件时，按修订值串行核对；写入冲突保留窗口稿和已生成内容，交人决策。
- AI 先出现在你按 `/` 的那段下面。位置不对就拖。模型不负责选落点。
- v0 的一场就是你一句、AI 一段。下一句是账本新的一章。新回答落在你新按的那个 `/` 下面；后续多轮交互另行拍板，不能把连续聊天当作本条的默认延伸。
- 点结束或关掉输入条、点到正文别处开始自己写、切 tab，都会结束本场输入交互；已提交的生成任务继续。Esc、停止按钮或关窗才取消仍在进行的任务。
- 没有「继续问」自动咬住上一块。还要聊就再自己找段首按 `/`。
- 未采纳的 AI 块留在任务发起时那篇里。切 tab 后任务仍可被查看和明确停止；生成结束不自动接续上一场对话。
- 生成中途可用按钮或 Esc 停。已写出的段落留下，仍是未采纳 AI 块。账本记「已中止」和当时那些字。

### 账本

2026-10-03 经用户批准替换同文件尾部账本。正文是当前文档权威，独立账本是过去任务权威，保存检查点只证明未完成保存；人删改正文不回改历史、不自动回填。删正文、清账本、忘记忆分别独立。

- 正文保留口令、可见回答及既有身份标记，不增加 noteId。库内 registry 维护逻辑 ID 与经核验对象关系；逻辑 ID 不替代身份或权限。每份账本保存有限归属描述供重建；损坏不得视为空记录。
- 应用保存由成功回执续接。外部改名移动仅在对象连续性唯一可核验时续接；路径、内容、task-id 只能辅助。未知归属显示“归属待核验”；单篇复制／导出为新笔记，另存新 ID 与明确恢复关系，整库迁移保留逻辑 ID 并重新核验。
- 每任务一份版本化 JSON：口令、可见回答、模型接收方、状态、来源、工具摘要和检查点。先持久化可恢复回答，再核验写回正文，最后对照两侧回执完成记录；不承诺跨文件原子事务，按任务 ID 幂等恢复，不重复调用模型。
- 主进程为唯一账本写入服务，渲染层只保存正文。分页回顾仍在同一 tab，只读、安全呈现，不入正文索引。原始回答永久作为历史，正文同步状态只凭明确回执；外部变化只标无法核验。
- 旧尾部先复制原始字节并复读核验，再按身份修订移除。保留 BOM、混合换行、文末与正文标记；不可解析章节保留原文回顾，不猜字段后入模。提供按篇及可中断的全库迁移。旧记忆依赖仅保留历史，不恢复许可。
- 新推理仅在设备临时区短期保存（七天／单场 32 KiB／每库 8 MiB），不进入摘要或记忆；旧推理迁移原样保留，仅人明确清理。清理留不含正文的状态，不阻断回答。
- 固定隐藏记录采用对象、修订、会话及库根核验后原子替换，接受最后核验到替换的残余换名竞态。此口径不适用于笔记删除或废纸篓；不声称安全擦除。单独拷出 Markdown 不再携带账本，整库备份须包含隐藏记录。

### 喂给模型

2026-10-03 合同：当前正文＋近期完整任务记录＋较旧摘要。摘要是低信任、有损、可撤销重建缓存，精确引用须回原记录，不能成为证据。

- 摘要最多两级，按完整任务组与依赖集合形成块，再汇总旧块；祖先继承全部依赖。变化按块及祖先失效，不能从散文扣一句话。原文与摘要覆盖互斥，清理原文即撤销对应缓存，部分清理标历史缺口。
- 固定六段：主题目标、人的要求、已完成结论、未决与受阻、后续上下文、须查原文事项；权威元数据由程序附加。最多四次增量更新，第五次从获准原记录重建。
- 缓存在设备应用数据目录；单篇 32 KiB（含依赖）、设备 128 MiB。隐私清单包括改写的笔记内容。允许跨接收方复用，但有效缓存不等于发送许可；记录生成模型、连接、主机、时间、格式与覆盖，授权浮层披露生成方，账本记录实际发送。
- 先扣系统／助手／协议／工具 schema／完整口令与必要落点／输出与工具返回预留／安全余量得到 B。正文预留至少 50%B；历史最多 min(8192,30%B)，记忆最多 min(4096,20%B)，摘要最多实际历史额度的 25%。剩余额度按正文、近期历史、相关记忆、旧摘要分配，仍守上限。
- 字节存储上限与保守 token 入模预算分开，每次序列化重新计量，估算与 API 实测分列。摘要、修复、重试共用同场预算且预留一次回答；不足省略旧历史并说明，必要项不足才拒绝。

### 库、文件、窗口

- 文件夹里已有的 Markdown 都是笔记，附件目录内的 Markdown 也沿用既有打开规则。笔记和其它直接资源在左侧栏下方列表中显示；上方只列普通目录。其它文件不按笔记打开。
- 每篇笔记自己带一个附件小文件夹，名字就是笔记名（`工作/会议纪要.md` 配 `工作/会议纪要/`）。图和 PDF 放这只夹里；插入附件时才建夹，不给空笔记预先建空夹。
- 引用写全路径：`![](会议纪要/pic.png)`、`![[工作/会议纪要/pic.png]]`。解析仍按 Markdown 标准相对路径走，软件不额外去同名夹里猜——这样同一份文件在别的编辑器里也显示得对。
- 文件名跟标题走。「会议纪要」就是 `会议纪要.md`，附件夹同名。不能当文件名的符号由软件替换。改标题就改文件名，附件夹一起改，库内 `[[全路径]]` 也尽量一起改掉。
- 人手动改名或移动时，先预览可能变化的 `[[全路径]]` 引用；只有确认后才逐篇按修订值修复，失败必须列出未修复项。AI 对其他笔记的结构操作不得借此改写那些笔记的正文。
- 平时自动写盘，也可随时手动保存立刻再写一次。不是纯手动。
- 并发替换只承诺两件事：不写出库外（判不出来就失败关闭）；到修订值核对点为止的外部改动能被发现并报成冲突。核对点之后、提交之前若目标被外部换掉，属已知残余窗口——两平台同一口径，没有可移植原语能表达「仅当目标仍是预期文件身份时才替换」，所以不承诺比这更强。**这个残余窗口是不报冲突、也不弹窗的**：下文「问你听谁的」只对已经发现的冲突成立，别把它读成残余窗口也交给人。
- 窗口里的稿和磁盘上这份文件不一样了，同时给出窗口稿与磁盘稿的两份预览，让人看清差异再问听谁的，不默默盖掉。**这句只管已发现的冲突**（见上一条的残余窗口）。
- 退出时保存失败，不得静默丢稿，也不得把应用锁在无法正常退出的状态；人能继续编辑、重试保存，或明确选择放弃未保存修改并退出。
- 可以开多个笔记 tab。正在看的那篇才是「当前这篇」。
- v0 不拆成两个窗。写字边界跟着当前 tab。
- 左侧栏可收起，默认收着；展开后按下方「侧栏目录与资源」分区。右边反链常驻。要翻目录再拉出左边。
- v0 要有反链。打开一篇能看到谁链到了它，按文件夹分组，点文件名跳转。呈现要组织得好看，不糙。
- v0 不做应用内历史版本。

### 侧栏目录与资源

- 上方只显示普通目录树。与同级笔记 Markdown 同名的附件夹（`会议纪要.md` 配 `会议纪要/`）及其整个子树不上树；普通目录中的文件也不上树。附件归属由主进程复用原生解析核对实际路径，大小写或 Unicode 别名不能靠渲染层猜测；沿用已有笔记／同名夹规则，显示分类不改磁盘布局、权限或 AI 读取范围。
- 下方显示上方选中目录的直接资源：笔记、其它文件，以及由附件开关控制的同名附件夹，不递归铺出后代资源。附件夹默认隐藏；开关为资源路径同行的眼睛图标，无文字且不单独占行，具有悬停提示与可访问名称／状态；开启后标明「附件」与所属笔记，不能把附件夹冒充普通目录。
- 进入附件夹时只切换下方浏览位置，上方选中目录和展开状态保持；下方能进入附件子目录、返回上一级，并返回所属普通目录。附件浏览始终显示归属和当前位置；其中 Markdown 按既有规则打开，不扩展非 Markdown 打开能力。
- 目录浏览和当前笔记 tab 分开：切 tab、从搜索或反链打开笔记不自动改变选中目录或下方位置。不设「定位当前笔记」按钮，人自行选择目录。
- 选中普通目录、目录展开状态、上下比例、附件开关、下方资源浏览位置与可选的侧栏首选宽度按设备、按库持久保存，不写进笔记库；使用渲染层 `localStorage` 保存非秘密、仅展示的浏览偏好，不作为身份或权限依据；上下滚动位置只在当前会话保留。换库不能沿用另一库的浏览状态。记录的目录或资源位置失效时，回到仍存在的普通祖先目录，无法确定时回到库根；不借旧路径重新打开内容。
- 侧栏可调宽度为 192–360px；默认展开宽度为 224px，内容窗口宽度不超过 820px 时为 208px。以同一窗口、同一阅读偏好和默认展开宽度时的正文行宽为保护基准：先缩小正文两侧留白，每侧最低 24px，再限制侧栏动态上限（1200px 内容窗约 320px，800px 约 256px）。窗口收窄只临时限制显示宽度，不覆盖首选值；空间恢复后自动恢复。收起时完整隐藏侧栏、边框与分隔柄，不留 48px 空壳；焦点在侧栏内时先还给顶部展开按钮，重新展开保留目录、附件浏览、上下比例和会话滚动。
- 上下默认按 40%／60% 分配可用高度，各自独立滚动；分隔条可拖动，也能聚焦后用键盘调节。保留现有搜索按钮与快捷键，不用资源列表替换全库搜索。
- 「新建文件夹」放在目录区，始终针对上方选中普通目录；「新建笔记」放在普通目录的资源区，附件浏览时隐藏该入口。顶栏 `+` 使用所选普通目录，侧栏收起及附件浏览期间目标不变；目录失效时要求重新选择，不静默改到库根。右键「在此新建」针对被右键目录。人的既有目录／笔记改名与移动仍走原预览和安全核验，附件内 Markdown 沿用既有安全操作路径；附件夹不能独立改名或移动，笔记连带附件的原规则保持。
- 本轮开放列表、导航、本机浏览状态、侧栏宽度调节与完整收起，保留 Markdown 的既有打开及人用安全操作；不扩展非 Markdown 打开、附件导入、删除、AI 写工具或新设置页。施工与待验收范围见[本轮侧栏分区](build.md#本轮侧栏分区局部授权)。

### 权限

- 三档：必须遵循、禁止触碰、可参考。未标明的路径默认可参考。
- 必须遵循只锁 AI：人能改这些笔记；模型不能写，`/` 只提示只读。
- 禁止触碰只挡 AI：人能打开、能搜到；不进模型检索，`/` 碰不到。
- 一份路径名单。设置界面改，真正写在库里隐藏文件。换机器、进 Git 跟着库走。
- 侧栏目录区对普通文件夹右键设档；未来设置页权限总表仍未开，不把合同中的规划当已交界面。
- 侧栏目录与资源项只给「禁止」和「必须遵循」打标。默认可参考不挂徽章。
- 权限名单模型不能改。规则文件 AI 不可写。人写盘通道也写不了这份文件。
- 对文件夹设档后，其下未另标的路径跟这档走。更长路径的条目覆盖更短的。
- 对一篇笔记设档时，同名附件夹（`会议纪要.md` 配 `会议纪要/`）及其下未另标的路径跟这档走。附件夹上若另有更长条目，以那条为准。笔记不因附件夹被设档而自动改档。
- 同一实际文件或目录的权限不能因路径大小写、Unicode 规范形式或并发替换路径而变弱；主进程无法确认路径与名单条目的对应关系时，AI 出口失败关闭。

### 检索与联网

- 不靠人在哪个文件夹里机械分类。专业问题由模型判断是否先搜本地、不够再上网。
- 「必须按原文」在提示里写死：涉及就查，回答要对着原文。
- 写盘仍不听模型：禁区碰不到，必须遵循的原文不能改。软件可抽查是否真的检索、引用。
- 人：v0 就能搜标题，也能搜正文句子。人搜得到禁止触碰；检索引擎是 v0 工程选型，见 [施工对象](topics.md#手动检索)。
- 模型检索不含禁止触碰，且只返回本场读取范围内的结果与路径信息。复用解析和匹配能力，但先固定本场获准对象，再读取、匹配、排序与分页，不能先用人的全库搜索后过滤；禁止建索引时把禁区抹掉做成唯一一份「看不见」的索引。人搜仍不受任务范围限制。
- 模型检索的方法不与人搜子串绑定。搜库工具返回带路径的可引用片段；倒排、BM25、按块切等未锁。向量检索不做。Host 最小环不提供搜库工具。
- 有应用级联网总闸：开仅表示允许提出搜索、抓页或 MCP 请求，不替代本场数据发送授权；关了关闭这些出口。总闸不关闭发起 `/` 所需的已配置模型文本接口，也不控制笔记图片展示；各用途分别授权和核验。
- 初期，受本地上下文影响的搜索、抓页与 MCP 请求，发送前展示实际内容、目的地和用途，经人确认才发出。读取笔记或允许送入选定模型不等于允许再送给搜索服务或 MCP；模型改写的问题、摘要和记忆也受此约束。不能证明请求只使用已批准的发送材料时须确认，不用关键词过滤推断“通用／不敏感”。同内容、同目的地、同用途的已批准请求可按有限重试规则重发；内容、目的地或用途改变须重新核验并确认。
- 禁止触碰的内容不经应用代转带出（模型上下文、应用发起的搜索与抓页、经主进程转发的 MCP 调用）。MCP 也不例外。无法代转的服务器不准接。必须遵循的原文只在有效读取和发送授权内使用，优先最少必要摘录；人的发送确认不能放宽禁止触碰或来源失效的限制。
- 抓回的网页进模型只准纯文本或 Markdown 摘录，当不可信输入，不得当系统提示。抽正文用哪套库、超时、体积上限未锁。
- 联网总闸独立于设置主入口。

### 沙箱与单场任务授权（合同与开放边界）

- 沙箱是 Host 执行请求与资源操作之间的基础安全体系，同时防范模型误操作和第三方组件直接越权。应用授权决定操作是否获准，执行隔离限制组件能直接接触的资源；两层都须有可核对的强制点。现有 renderer sandbox、固定库根 IO 和无工具 Host 不代表完整 Agent 沙箱已经交付。
- 有效权限取应用已开放能力、库内三档权限、单场任务范围、工具限制及当前对象状态的交集。未开放的能力默认拒绝；未标记路径默认可参考的原规则保留。人可通过独立入口读写禁区，模型和第三方组件不能借用人的通道。
- 单场读取默认限发起篇正文及本篇账本。人可为本场明确授权其他笔记或目录；模型可请求扩展，但不能自己批准。读库／搜库只在该范围与当前三档权限的交集内工作，跨篇结构授权不隐含读取权。展示读取范围时同时说明内容会进入本场选定模型端点；云端模型即对应供应商接收，单场更换模型端点也须让人核对接收方。范围与接收方确认必须先于 Host／工具读取或向模型发送；主进程可在本地准备预览时读取对象、权限与修订用于核验，不向模型发送；未确认不得开始本场。
- 读取、向选定模型发送、向搜索／MCP 等外部服务发送分别受控。写入既有正文固定为发起篇及本篇附件；库内新建须明确授权目标范围，不能借新建覆盖另一篇已有正文。范围确认不放宽有效库权限，也不隐含结构操作或对外发送授权。
- 跨篇改名、移动默认没有授权。人可在任务开始时圈定范围，或在模型提出操作后看过对象、目标和影响的预览再授权；本场任务可在指定范围内连续执行，无须每项重复授权。来源、目标位置及同名附件须在授权覆盖内，目录操作核验整个受影响子树；范围扩展必须由人重新确认。删除仍须逐次确认，且受系统废纸篓安全门约束，范围授权不能替代它。
- 授权绑定当前库会话、任务和对象身份，不按裸路径字符串继承。每次操作仍复核有效权限、身份、内容修订、目标和预览；合法保存／移动只有经受信任服务核验后才能续接对象绑定，不能扩大原授权范围或正文写入权。换库、任务结束或取消后授权失效，权限收紧即时影响下一次使用，外部替换的新对象不能继承旧授权。任务配置快照不冻结权限；范围内出现变化也不能省略重新核验。
- 文件、网络和凭据操作经受信任的资源服务；模型与第三方组件没有通用读盘、直接联网、读取密钥或更改门禁的入口。模型 API、Agent 搜索／抓页、MCP 与图片展示各核对用途、目的地和允许发送的数据。密钥按连接留在受信任服务，只用于指定服务的必要认证，不作为模型内容或本机服务器环境变量，不跨连接串用。
- 笔记、账本、记忆、技能、网页和 MCP 结果均不能增加授权；助手人格与习惯也不改变能力边界。摘要和工具结果须保留来源约束，每次发送前复核，来源失效后不能继续借副本向模型或外部服务发送内容。已获准发出的请求不能承诺追回；发现撤销或来源失效时停止后续调用，尝试中止在途请求，不能把旧上下文继续当作有效依据。
- 可执行第三方组件在接入前须验证文件、网络、进程创建及必要资源上限；取消、崩溃和超限后停止后续操作，保留已产生内容与可核对结果。无法证明隔离时保持能力关闭，不降级为高权限执行。具体平台机制、限额和授权控件仍须工程验证。
- 沙箱不替代库根、对象身份、修订值、冲突及中断恢复边界，不改变既有文件操作的残余竞态承诺，也不提供历史快照或自动回滚。它约束 Rgent 启动的组件及应用出口，不承诺约束同机管理员、内核或已获准接收数据的远端服务内部行为；无法在此边界内控制的 MCP 能力不接入。

工程方案与验收见 [施工对象 · 沙箱与任务授权](topics.md#沙箱与任务授权)，前置依赖见 [施工图交接表](build.md#跨能力交接)。本节的分包开放与进度只以施工图为准；MCP、通用联网、写工具及新设置页仍未开。

### 单场授权与首批只读工具

- `/` 口令旁浮层展示发起篇、固定参考范围、模型及实际接口主机，并说明资料会发送给该接收方。回车确认并发送、Shift＋回车换行；输入法组合不发送，取消准备保留口令。提交前排空人的草稿，预览失效或配置／来源改变须重新展示并确认。
- 默认仅发起篇正文及本篇账本；额外笔记／目录展开为固定 Markdown 对象集合，新增成员不继承授权，其他篇账本、附件、隐藏与非 Markdown 对象不开放；同名附件夹及其整个子树中的 Markdown 不得作为发起篇或参考来源，主进程依据实际文件系统归属排除并持续复核，不能仅信界面标签。来源失效停止整场后续调用并保留已有结果，不自动恢复。
- 首批仅「读库」「搜库」：按授权范围先限定对象，再匹配／排序／分页；不调用人的全库搜索后过滤。返回可核对的来源和省略／续读信息，不无界铺送全文。默认范围沿用无工具档，额外参考采用本地档及设备上限快照；模型、摘要、工具尝试及失败重试共用单场预算。
- 模型单步返回文本、推理及工具请求，Host 校验名称／参数并依序执行；SDK 不自动执行或隐藏循环。协议不支持时显错，不切供应商、不改为隐式全量发送。工具原文及参数不铺进正文，思维链不进正文；过程与来源写入结构化账本，新推理只按「喂给模型」的期限与容量存设备临时区，不进入摘要或记忆。旧推理随迁移保留。
- v1 任务章追加版本化机器来源依赖，记录实际模型、授权概况、工具摘要、实际读取／发送的来源及中止原因；不存密钥或重复外篇全文，不改旧章字节。历史外篇依赖在后续入模／摘要前重新核对本场范围、身份、权限和内容；无法核验则省略并说明。旧无工具章节保持兼容，损坏新记录不得降级成无依赖。
- 授权仅内存、单场有效且一次性绑定；取消、超限、换库和结束撤销后续读／发送。可信收尾只保存已产生文字及同篇账本，仍核最新权限与对象；失败保留待保存内容。它不等于完整 Agent 沙箱或第三方执行隔离。

### 模型

- v0 就能换厂家，也能填兼容 OpenAI 的接口地址。
- 预置 DeepSeek 与 MiniMax。MiniMax 默认国内 `https://api.minimax.cn/v1`，国际候选为 `https://api.minimax.io/v1`（2026-10-04 用户纠正）；密钥与端点绑定，跨端点不通用。接口地址始终由人填写或改定，预置只登记「已知端点」作候选。变更预填地址不自动覆盖已经保存的连接；本次另获用户授权更正现有 MiniMax-M3 连接地址。
- 模型设置按设备保存；预置之外的兼容接口地址只接受 HTTPS，或指向本机回环地址的 HTTP。带密钥的模型请求不跟随重定向。自定义模型需填写上下文窗口容量；模型配置与运行上限在每场任务启动时固定，运行中修改只影响新任务。
- v0 用 Electron `safeStorage` 加密密钥，密文只存应用数据目录，不进笔记文件夹或仓库；解密材料由操作系统保护。发行前分别验证 macOS 签名后读取与 Windows DPAPI 行为。
- 不可加密或解密失败时明确报错，不退回明文。界面只显示密钥保存状态，允许替换、删除；切换供应商不把上一家的密钥发送给下一家。
- 本机模型（Ollama 等）不进 v0。
- 不配密钥也能用笔记。配了才有 `/`。
- v0 一个供应商只配置一份凭据：每个供应商至多一条连接（端点 + 一套独立加密的密钥），同一供应商不得存在第二份配置；不同供应商之间密钥不串用。一条连接下可以有多个模型（模型 ID 与上下文窗口容量）。
- 设置页「模型」是人**配置**的地方：根页按供应商列出（DeepSeek、MiniMax、自定义兼容接口）并显示各自的密钥状态与模型数，点进该供应商的子页配置端点、密钥与模型清单；子页有明确返回入口。它不设「当前模型」控件；设备默认模型在「助手」页独立保存，底栏只临时选择下一场模型。界面不为单一厂商开特例控件；已知端点只作接口地址的候选，字段本身是唯一真源。
- 「读取模型」只由人在设置页对**当前连接**发起：一次只读请求（HTTPS 或本机回环，不跟随重定向，超时与响应体有上限），只取模型 ID 与端点自报的上下文容量（若有），结果作为**候选**由人勾选后保存。它不写账本、不进单场授权、不扩大任何范围，也不后台轮询、不缓存到设备。
- 端点没提供上下文容量时必须由人填写，界面说明原因；不设默认值、不猜。
- 设备默认模型在「助手」页独立保存，按设备跨库共用；新设备默认空，供应商／模型配置不自动选默认，已有有效默认与旧配置迁移结果保留。默认删除或不可用时明确提示，不静默选择其他模型。**底栏中间的模型模块**只显示名称，按供应商分组列已配置完整的可用模型；临时选择按当前笔记仅存内存，切 tab 相互独立，无临时选择时使用设备默认。任务启动成功后清除该篇临时选择；取消准备和启动失败保留。关 tab、换库、重启清除；受控改名移动可续接，外部替身不可继承。默认改动不覆盖临时选择；临时模型失效要重新选择，不悄悄回退。无活动笔记不创建临时选择，缺配置给引导。授权预览显示实际模型与主机，并绑定所选模型记录，变化后须再次确认。

### 助手与连接（当前阶段）

分两块做，先多连接与模型，再助手习惯；本阶段范围与顺序见[施工图](build.md#助手与多连接已交)。

- 先提供**一个可自定义助手**，设置里有独立一页：**称呼**（怎么称呼你，可为空）、**语气**（平实／简洁／详尽）、**补充说明**（一条人写的附加要求，≤ 500 字）。称呼为单行，补充说明允许正常换行，其他禁止控制字符继续拒绝；输入保留原样，只在保存时处理首尾空白。三项按设备保存、所有笔记库共用；保存才生效，另有恢复默认。设备默认模型为同页独立配置区域，与习惯分别保存并分别报告结果。
- 助手习惯只拼进模型的系统提示（任务启动时取一次快照，与模型、上限同样在启动时固定），并在系统提示里说明它不改变本场范围、工具与权限；它不改变界面文案，也不进工具、不进范围。
- 本篇账本记一行摘要说明该场用了什么习惯（例如"助手习惯：已应用（语气=简洁）"），只记摘要不铺全文。缺失或损坏的本机偏好用默认值，读取不覆盖原文件。
- 它们不赋予助手越过笔记权限或后台扫库的能力。多助手保留为以后讨论的可能，不预设身份切换或自动编排。
- 多个供应商连接可并存，每个连接的密钥独立加密和读取，不把一个连接的密钥发给另一个。设备有默认模型，发起单场任务时可临时选择其他已配置模型；启动时固定连接、模型、端点、密钥归属和运行上限的快照，运行中修改只影响新任务。失败不得静默切换到另一供应商。先交付多连接与隔离，再逐种验证新协议；OAuth、Coding Plan、本地模型等均不因参考产品截图自动开放。

### 库内记忆

#### 2026-10-05 v5 本库工作接续记忆（局部授权）

自动记忆收窄为**本库工作接续**，只存三类：近期工作背景、长期约定、项目事实。近期背景是有期限的任务块，每块按 `goal / completed / blocked / next` 四段记录，最多 32 块、14 天；**一块四段合计文本**最多 2 KiB，单块编码最多 16 KiB，全部近期块编码最多 128 KiB。长期约定与项目事实合计最多 1000 条，整份记忆文件最多 2 MiB，新增和遗忘仍须保留可证明的控制与遗忘空间，满容量不静默淘汰未覆盖的约束。独立更新预选池最多 64 个候选，实际发送给整理模型最多 16 个候选，模型最终提出的长期记忆动作最多 16 个；每项标签最多 6 个。模型输入中的记忆总预算为 `min(4096 token, 20% × B)`；其中长期约定最多 2048 token，近期背景最多 1024 token／4 块，项目事实使用剩余额度且最多 2048 token／8 条，所有分项仍受总预算限制。

一期整理每次最多一次模型调用，可选一次**仅格式修复**；不默认追加第二次语义审查。来源、内容、启用与容量分别记状态，不能把可读、来源未变、许可有效或有空位相互代证。快照只读，发送边界再次核验，写入走整文件 CAS。裸口令不继承整场依赖；从材料派生的内容沿保守依赖闭包核验，近期块的遗忘闭包与长期记忆同样执行。现有 v4 恢复、正文保护和授权边界保持。

新版本与现存记忆格式不兼容：旧数据只作为识别、核验与目标退役对象，未知格式显示诊断，不当空记忆、不自动覆盖。退役不删除人的笔记、原账本、凭据或设备／库配置。双模型实测达下述门前，开发版默认保持现状；正式学习质量提示不消失，既有开关不因实验结果自动改变。上述为批准的施工合同，接线与切换结果以施工图逐包证据为准。正常应用保存的已核验对象回执允许持久续接仍能唯一对应的来源；外部同字节替换不能据此认领。一个批次更正了旧版本时，依赖该旧版本的其他新派生内容须暂不提交，不能凭新内容与旧内容等价的假设改写依赖。

真实模型验证仅用于后台整理的官方 `deepseek-flash` 与 `MiniMax-M3` profile：`thinking.disabled`、正文输出上限 4096 token。MiniMax 国内端点不改真实配置，回答正文模型保持原选择。固定虚构数据、提示与评分后，分别对两模型各跑两轮；每轮 30 次 attempt（20 个独立案例及两条各五步的接续链），每次一次提议调用，只有格式错误才可增加一次格式修复调用。240 次包含所有实际派发、失败和取消，从 v4 后余额 612 次划出；不提供额外网络重试额度。首 10 个平衡样本最多 40 次调用，先作分模型停损；误归属第三方、单次要求长期化、含糊冲突任一出现即该模型停止，服务不可比时暂停并保留分母。长期约定与项目事实正例总体 ≥95%、每组 ≥90%；近期背景正确率 ≥90% 且无虚构。两轮、双模型全部达门才可切开发版默认；这不等于正式学习质量通过。实验结果、计费次数、失败及未执行范围须分别登记，不用一模型成绩补另一模型。

**三道验收门**缺一不可：学习质量门（上述分数）；运行可靠性门（每模型每轮 30 次计划尝试中取得完整可解析结构化输出的比例 `P/N ≥ 95%`）；证据充分性门（每例有明确状态、≥27/30 有可判定系统结果、每方向独立案例覆盖 ≥80%、每类关键安全负例 ≥2 处可判定且共 3 处覆盖、输入／准入／最终存储／下一场装入与来源证明齐全）。另报派发覆盖率 `D/N`、完整响应获得率 `T/D`、结构化输出成功率 `P/T` 与首调用成功率；传输与服务失败单列，不得据此直接称模型语义能力不足。权限、来源、遗忘与保稿等工程安全门独立，不能用学习分抵消越权或存储缺陷。

**三项即时否决**只对最终有效记忆或实际使用内容生效，且必须双标注：第三方要求误归属为本人、单次要求长期化、含糊未确认矛盾被自动采用。原始提议出错但被程序完整阻止**不触发**否决，只报原始提议错误率；v4 的另两类（禁止内容、范围扩大）降为维度内必判检查项。取得正文却无法判定的语义结果按**上下界**记分，只有下界达门才可宣布通过；上下界不是置信区间。缺关键安全证据保持证据不足。

**裁判协议**：程序判执行事实（是否发送候选、是否提交、版本、状态、实际装入），Agent 按冻结协议判语义，人工复核单独记录且不得由 Agent 代填。每份标注保存案例、结果与规则指纹、裁判身份及是否参与实现或提示编写、逐信息单元判定与原文、动作与归属范围判断、否决项、不确定项与理由、修订历史。证据不足必须引用**预登记理由**（无模型输出、终态回执无法绑定本次尝试、安全关键来源映射缺失），其余一律必须判定。每模型每轮抽 ≥10 例独立双标并报告一致率，分歧进"不确定"且永不计为通过；遮蔽模型名不等于盲评。本轮允许披露身份的 Agent 标注；未取得人工复核时界面与报告显示"未人工复核"。是否要求关键安全案例必须由人确认属新增决定，须另行批准。

### 技能

- 技能是 prompt 说明文。不是文件树里的文档，也不是 MCP。
- 人只能在设置里技能这一页打开编辑。
- 磁盘上跟库走，对文件树隐藏。文件树里没有技能文件。
- 做好不等于能用。必须有加载、卸载。只有人点加载、卸载。没写完也能先存着。名字、什么时候用、具体怎么做都写齐了才能加载。
- 没加载的只待在技能库，不进 `/` 候选栏。卸载后文件还在。模型不能自己上架。
- 生成技能两条路：
  1. 设置里点「制作技能」，按内置模板手写，产出未加载技能文件。
  2. 在可写笔记里用 `/` 把需求谈清楚，浮栏里用内置「生成技能」。先确认会新建一份未加载技能、这篇笔记不删不收走。点头后另外新建一份完全按内置模板填好的技能文件，未加载、树上看不见。原笔记原样留着，文件树不动。
- 新建后立刻打开设置里技能这一页这份未加载技能，由人检查再决定加不加载。
- 制作过程留在原来那篇笔记里，不进技能。
- 技能按软件内置模板把事说清楚。人不改这份模板。就地收走、删笔记、账本进技能包均作废。
- 禁止触碰的笔记不能拿来生成（正文不送模型）。必须遵循里 v0 的 `/` 仍只提示去可写笔记，不在这篇里生成。
- 「生成技能」是内置动作，不是某个已加载技能。
- 技能只在设置的技能页里删。卸载只是不用，删除才从库里拿走。
- 一按 `/` 立刻浮出已加载技能的全量可滚动候选栏。一次只能绑一个。打字或空格即放弃注入。
- 口令上必须明显标出技能名。

### 工具

- 库内文件工具的规划清单七件：读库、搜库、建、补任务发起篇、改名、挪、删（删须人确认）。「写稿」是建 / 补 / 改名 / 挪 / 删五件的合称，不要求五件同时交付；删除独立过安全门，未验收时不注册该工具。库内工具清单只此一份，其它篇不要再列。受控联网和逐项审定的 MCP 是外部能力，不据此新增任意库内操作或承诺固定的外部工具总数。
- 设置里只可接逐项审定且通过 [沙箱接入门](#沙箱与单场任务授权合同与开放边界) 的 MCP 白名单服务器。不接也能用；任一平台无法证明文件和网络出口受控就不接入。关闸或无法代转则不准接。
- 技能是说明文，MCP 是手。两套不能混成一种。模型不能自己接上 MCP。
- MCP 首批只审定远端 HTTPS 的只读查询、资料获取。每项写清工具、发送材料、目的地、凭据、结果来源、超时／取消与部分失败；返回值和动态发现的工具均不自动获得权限。外部写入、发送消息、发布及账号修改另行讨论并验证，不能借“只读连接”开放。本机可执行 MCP 保留为后续能力，隔离门未过时不普通启动补位。
- 生成任务只编辑发起时那篇笔记的正文和本篇附件；可在 [单场授权范围](#沙箱与单场任务授权合同与开放边界) 内对其他可参考笔记改名、移动，或经人逐次确认后删除，但不能编辑它们的正文；可移动受影响内容全部可参考且在授权内的文件夹。不提供递归删除文件夹。删除单篇笔记及其附件须逐次由人在弹窗点头。
- 工具执行前逐项检查来源、目标与受影响子树，不能靠改名或移动改变禁区的实际保护范围。库内容、网页和 MCP 返回值一律作为低信任数据进入模型上下文。
- 人工结构操作可连同对象迁移显式权限规则；中途失败或规则冲突不能让实际保护范围变弱。AI 结构工具仍待文件生命周期基础能力交付后接线。
- 要改另一篇的字，得先打开那篇再发起新的 `/`；切 tab 不改变已提交任务的目标笔记。
- 必须遵循不能改字。禁止触碰碰不到。不是后台扫库。

### 设置里有什么

- 一个设置界面，未来按工作对象分组：工作区「笔记库、通用、界面」，Agent 的助手行为、库内记忆、模型与运行、权限，连接与扩展，以及应用信息。记忆页按上文批准合同；其它未交付页面的名称与控件仍待施工前确定。技能不单独再做一个面板；只显示已经可用的页面。库内记忆前置本机功能门通过后已接入第五页，2026-10-04 另开放「笔记库」页，当前为「笔记库、界面、助手、记忆、模型、运行」；本机及其它平台的验收状态见施工图，不以显示页面代称阶段验收。页面增多后再开放设置搜索。
- 设置入口固定在**底栏最左侧**：只要图标、没有文字，命中区域足够大、可键盘聚焦，不随文件树或画布滚动。设置主页面及所有层级的子页面，沿用 [前端协议](frontend.md) 的工作区视觉语言；整个设置面板悬浮在正常工作区上方且面积更小。浅色主题里侧栏与内容画布都采用浅色。打开设置时工作区柔焦并压暗，面板保持清晰；点击面板外或按 Esc 关闭并返回原焦点。当前另开放「助手」「模型」「运行」页的必要控件；其余设置子页仍待逐项讨论。
- 主题、阅读排版及界面文字偏好只保存在本设备应用数据目录，重启及换库后沿用，不写进笔记库。跟随系统时响应系统外观变化；选定日间或夜间后不随系统变化。正文与标题字体分别从精选方案选择；正文字号、行距、最大阅读宽度在设置样张内先预览，确认保存后应用到本设备全部笔记，放弃未保存的调节则不改变工作区或 Markdown 原文。未来画布顶部篇名沿用标题字体；显示并直接改名另行施工，须连同附件夹、引用、tab 与 Host 任务一起验收。
- 界面页分别提供 tab 名称、侧栏目录与资源字号的「小／默认／大」有限档位，保留现有字号为默认；小减 1px 且最低 12px，大加 1px。只预览样张，保存成功才应用，取消或失败维持旧值。按设备跨库保存，不改根字号、正文排版或窗口缩放；具体工程值随真实窗口验收调整。全客户端任何可点击组件在任何状态下不得有紫色包围边框、轮廓或环形阴影，点击使用背景／填充反馈，键盘焦点使用清晰的中性样式；单侧标识、文字与任务状态仍可用强调色。

- 已点名会进设置的至少有：库路径、一个助手的设备通用习惯、当前库的记忆查看与删除、多连接供应商及密钥、模型默认值、Agent 运行上限、权限总表、技能（制作、编辑、加载卸载、删除）、MCP 连接。单场模型临时选择属于发起任务的交互，不靠设置页替代；运行上限不能设成无限制或绕过门禁。

## 单窗口多库管理

- 客户端永远只有一个应用实例、一个工作窗口、一个活动库；多个库仅在应用内切换，不开放同时运行多个库。
- 设备保存已登记库目录，支持打开现有库、创建空库、固定、修改显示名称、重新定位及移除目录项。移除不删除任何库文件、账本或记忆；显示名称不改磁盘目录名。真实根目录相同的别名视为同库，已登记库不得相互包含。
- 启动恢复最后成功使用的库。根消失、被替换或无法核验时停在选库，不静默回退。目录损坏保留诊断和手动打开入口，不当空目录覆盖。迁移、复制或重新定位不得自动继承设备发送许可。
- 每库自动保存设备工作区：tab 顺序、活动篇、光标选区、阅读位置、侧栏显示和滚动。恢复时读取最新磁盘正文，缺失对象标明，不自动重建。任务、授权、临时模型、正文草稿、撤销历史不随工作区恢复。既有浏览偏好继续用非权威 localStorage。
- 目标预检只读，不运行恢复、迁移或整理。目标选定后处理未保存设置；当前任务仍运行时由人确认停止，保住已有回答与账本，保存所有正文，停止后台整理并排空队列，重核目标后提交活动绑定。取消选择不停止当前任务，保存失败留在原库。提交后的初始化失败显示新库诊断，不声称跨库原子事务或静默回滚。
- 原库预览、异步响应、事件与媒体绑定当前库会话。旧绑定不得在新库同名路径读写；设备模型密钥、助手与外观全局共享，权限、记忆及库内容按核验库身份隔离。

- 库管理统一纳入设置「笔记库」页，位于工作区分组、界面之前；普通打开设置仍默认界面。右下角库名只读，原生菜单与启动界面管理入口进入同一设置面板，不保留独立库管理浮层。当前库单独展示，其余固定优先、再按最近使用排序；名称不触发切换，切换使用明确按钮。正在使用的库不能重新定位。
- 从笔记库页发起切换，准备阶段保留设置；收到新库已提交状态并进入恢复门后关闭。忙时暂停页面、导航和关闭，取消或失败保留输入、展开和焦点；显示名称草稿独立管理，不将已保存名称误判为未保存设置。
- 2026-10-06 **根身份跨重启的判定**（来自本机实测事故）：根身份是 `设备号:inode`，APFS 上设备号跨挂载／重启会变而 inode 不变。因此"设备号变、inode 不变"记为**卷重新挂载**，不是被替换：停在选库并说明可用「切换」确认打开；人在库列表点该库的「切换」＝确认同一个库，此时改记新设备号并把该路径的工作区登记一并换绑，保住 tab 与阅读位置。**inode 也变**仍是 `VAULT_REPLACED` 硬拒，不静默重绑、不自动继承发送许可。三种失败（被替换／换了位置／目录不可访问）在界面上分开说明，不共用"身份发生变化"，也不把"无法打开"与"目录不存在"混写成一句。选择库页的按钮行必须有间隔，相邻操作按钮不得贴成一个色块。

### 2026-10-04 记忆质量验证与债务修复（局部授权）

当前阶段仍为库内记忆。固定虚构资料验证 MiniMax-M3 与 deepseek-flash，各 120 例、每例三次，分别报告结果；十组各 12 例：明确长期要求、已确认项目事实、明确更正、重复表达、单次与临时要求、引用与第三方要求、未采纳回答与模型猜测、含糊矛盾、范围与时效、恶意材料与伪造引用。每组最后四例为保留集，共 40 例；样例、标签、分组和保留集先固定，不能看到保留结果后改提示再称独立验证。

误归属第三方、单次要求长期化、含糊冲突采用仍为零容忍，任一发生即失败；正例保留率总体 ≥95%、每组 ≥90%，按各模型分别报告三次结果及困难案例，不能合并模型或组别掩盖失败。固定标注 1000 条记忆／100 个查询，Recall@8 ≥85%、无关比例 ≤5%；计算口径、相关标签与失败查询随证据保留，不以人为关键词特判补分。
