# 已拍板决定

本文是围栏对照表。改产品性格先改这里，再改 [理念](vision.md) / [架构](architecture.md) / [施工守则](handbook.md) 和代码。

只收录讨论里已经点头的结论。文中 **v0** 指围栏内第一代可安装客户端，不是商店版本号。

## 1. 产品根

- 单机笔记 + 个人资料库。Markdown 是唯一真相。
- 所有对象都是同一类 `.md` 笔记。没有「正规笔记文件」与「对话文件」两种类型。
- 润色、扩写、缩写、问答都发生在当前笔记页，写入同一份 Markdown。没有第二套 Agent 会话区。
- 磁盘呈现：成稿优先干净。对话用约定区块包在同一文件里，换编辑器时不抢视觉。应用内可展开、可写入成稿。分界在呈现，不在文件种类。

## 2. 库与权限

- 库是用户自选的一个普通文件夹，可放非系统盘。一篇笔记一个 `.md`，子文件夹既是分类也是 AI 权限边界。图片与附件用库内相对路径。
- 应用设置（窗口、上次打开的库路径）可留在系统侧。密钥只进操作系统凭据库。笔记内容不进应用私有库。
- 三档规则写在库内，应用执行，模型没有投票权。换机器、进 Git，规则跟着文件夹走。
- 规则文件所在目录对 AI **禁止写**（建议也不当普通笔记检索出来）。
- **禁止触碰：** 不进索引；读/写/列目录工具直接拒绝。
- **可参考：** 可检索、可读；写操作走下面的文件工具白名单。
- **必须遵循：** 相关问题**强制**检索并引用；**只读**。改原文只能用户动手。
- 失败则拒绝。「禁止」压过「可参考」。子目录继承父规则，更严的覆盖更松的。
- 单文件 frontmatter 覆盖第一版不做，避免模型改一篇 frontmatter 就给自己放行。

## 3. 编辑与渲染（v0 合同）

- 默认 Typora 式所见即所得：光标在段落里才露出源码，离开即渲染。必须能一键打开纯源码（查坏语法、frontmatter、幕后对话区块）。
- 打开一篇笔记，v0 就要站得住，且解析与显示同一套引擎：
  - GFM（标题、列表、任务、表格、代码块、链接、图片、引用、脚注）
  - YAML frontmatter
  - 数学公式
  - callout / admonition（给人写的；**不是**拿来藏 AI 会话的）
  - `[[双向链接]]` 与嵌入
  - Mermaid
- 公式、Mermaid、wikilink、嵌入、callout 必须在所见即所得流里成立，不能靠切到预览才能看。
- **内核：CodeMirror 6 即时渲染。** 缓冲区与磁盘都是 Markdown 字符串，不是整篇富文本 AST。光标所在行露出源码标记，离开后用 decoration / widget 显示排版。这是为了长文性能，并守住「md 是根」。
- 公式、Mermaid、`[[wikilink]]`、callout、嵌入做成 **viewport 内 widget**，进入视口再加载（懒加载）。表格与图同样用 widget 补表现力，不为此把文档模型改成 ProseMirror / TipTap / BlockNote / Lexical。
- 周边封装（是否用 Silkdown 等 CM6 扩展层）未锁，但不得改成 AST 路线。
- **P0 压测：** 用 5～10 篇含公式、图、表、双向链接的长文测滚动与输入延迟，把数字补进本节。压测用来调 widget 与懒加载，不用来改回 AST。

## 4. 壳与运行时

- 壳：**Electron**。第一版就要能在 **macOS 与 Windows** 上装。
- 打包：Mac 优先 `arm64`，Windows `x64`，**分架构出包**，不打 Mac Universal。Intel Mac 可另打。
- 一个主进程 + **一个**渲染窗口。渲染进程无 Node、无任意路径。
- 产品逻辑纯 TypeScript。不上 Python 边车，不上 Pydantic AI，不上 Tauri 业务代码。
- 控体积与内存：按架构出包、砍掉不用的 Chromium 语言包、asar、重型语法懒加载、一次只把当前篇灌进编辑器、文件树虚拟滚动、单实例。不把整库正文载入内存。
- Chromium 是地板：不为「接近 Tauri」去关硬件加速或上 UPX。

## 5. Agent

- Agent 是主进程里的 **文档操作器**（`AgentHost`），不是独立产品。
- 模型与流式工具调用：[Vercel AI SDK](https://ai-sdk.dev/)。MCP：官方 TypeScript 客户端。编排、三档权限、写回策略由本应用写死。
- 三种模式（同一套工具，不同写回）：
  1. **改写：** 选区润色/扩写/缩写 → 改当前缓冲区；对话可只进幕后区块。
  2. **问答：** 提问在页内；答进幕后区块，需要时再写入成稿。
  3. **强制检索：** 当前笔记或问题命中「必须遵循」领域时，先本地检索再回答。
- 记忆 = 当前 md（含幕后区块）+ 本次工具读到的许可片段。没有平行 session 库。
- Skills：库内 **prompt-only** 的 Markdown，按文件夹/领域注入，**不执行代码**。
- 厂商可切换；密钥进系统凭据库，环境变量仅可选覆盖。
- **Harness 做实，外循环以后再说。** 吸收时下 Loop / Harness 工程的分层，但不在 v0 做人离开后无人值守扫库。
  - **Harness（v0 / P2 起必须具备）：** 一次页内任务是「目标 → 工具 → 观察 → 是否继续」。硬刹车（最大轮数、超时、费用或 token 上限、同一工具同一参数空转则停）。工具错误写给模型看（例如「该路径只读，请改为新建笔记」）。写操作尽量可重试（优先 `vault_replace` / `vault_insert`）。「完成」不能只听模型自报：必须遵循的问答要能核对是否检索并引用了原文；删除以用户确认为准。长上下文要压缩；轨迹可复盘（幕后区块或运行日志能看到本轮工具调用）。
  - **外循环（方向，非 v0 主线）：** 定时或「改到引用齐」之类的触发、maker/checker 分开验收、状态写在库内以便接力、失败则重试/问人/停止。接口可留，v0 不实现无人值守改库。

## 6. 工具白名单

每一种落盘动作单独成工具，便于 ACL 逐项拒绝并留下调用记录。没有 Shell，没有万能 `run`。

许可范围：**可参考**路径，以及当前正在编辑的笔记（含未保存缓冲区）。禁止触碰、必须遵循、规则目录上即使模型点名调用也直接拒绝。

| 工具 | 做什么 | 约束 |
|------|--------|------|
| `vault_list` | 列许可范围内的目录 | 禁区不出现 |
| `vault_search` | 本地全文检索 | 禁区不进索引 |
| `vault_read` | 读文件 | 禁区拒绝；必须遵循允许读 |
| `vault_create` | 新建 `.md` 或许可下的子文件夹 | 禁区 / 必须遵循 / 规则目录拒绝 |
| `vault_insert` | 在标题、行号或书签后插入 | 同上；长文改写的首选之一 |
| `vault_replace` | 文件内旧文本 → 新文本 | 文字增删改的主力，避免整篇覆盖 |
| `vault_write` | 整文件写入 | **克制**：仅新建初稿或模型已读过的短文件 |
| `vault_rename` | 重命名或移动（许可范围内） | 不得挪进/挪出禁区或改掉必须遵循原文路径来「绕过」只读 |
| `vault_delete` | 删文件或空目录 | **必须在 UI 里经用户确认** 才落盘 |
| `editor_insert` / `editor_replace` | 改**当前打开、可能未保存**的缓冲区 | 与磁盘工具分开，避免盘上已新、窗口仍旧 |
| `web_search` | 联网搜索 | MCP（如 Tavily、AnySearch）或模型自带搜索 |
| `web_fetch` | 抓取 URL | v0 仅 HTTP；接口名固定，便于以后换成 Electron Chromium |

`editor_*` 负责页内润色和当前篇问答写回。跨笔记整理走 `vault_create` / `vault_insert` / `vault_replace`。

## 7. 网络与浏览器

- v0：HTTP 抓取 + 搜索 MCP + 模型自带搜索。
- 以后若需渲染 JS：复用 Electron 自带的 Chromium（隐藏窗口或 CDP），**不打进 Playwright 第二份浏览器**，除非单独立项并改本文。
- Pydantic AI / Harness 浏览器 extra 不是产品内核。

## 8. 第一版阶段

都要在 GitHub 上留下可运行增量。前一阶段没站住，不开始下一阶段当主线。

| 阶段 | 交付 |
|------|------|
| **P0** | 选库、文件树、打开/保存、CodeMirror 6 即时渲染、第 3 节语法合同与 viewport widget、崩溃不丢当前文件。用 5～10 篇含公式/图/表/双向链接的长文压滚动与输入延迟，数字写入第 3 节。无 AI 也能当笔记软件用。 |
| **P1** | 库内规则文件、三档 ACL、FTS 索引。测试钉死：禁区读失败；必须遵循只读。 |
| **P2** | 页内 AI、Harness 内循环（刹车、错误回喂、完成核对）、流式写回、幕后区块、`editor_*` 与磁盘文件工具、密钥与厂商、强制检索。删除走确认框。 |
| **P3** | 至少一种搜索 MCP、skills 目录。`web_fetch` 仍是 HTTP。 |

云端可先把渲染器当网页开发，本机再套 Electron 验窗口与凭据库。

## 明确未锁

- CodeMirror 6 的具体封装包（是否用 Silkdown 等）；P0 压测阈值（补进第 3 节之前先写实测）
- 幕后对话区块的具体围栏语法
- 库内规则文件的文件名与 schema
- FTS 引擎（SQLite FTS 等）
- 「必须遵循」领域如何判定（当前笔记所在目录、用户点名、标签；不能只靠模型自觉——具体组合未锁）
- 第一批接入的模型厂商清单与 MCP 服务器清单（至少一种搜索 MCP 已锁）
- 文件树/主题/快捷键具体绑定
- macOS / Windows 最低系统版本、自动更新
- 是否做 Intel Mac 官方包

未锁项要落成围栏时，先改本文再施工。
