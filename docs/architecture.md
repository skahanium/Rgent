- **渲染进程：** 画布是 CodeMirror 6。文档是 Markdown 字符串。无 Node，不能直接读写库文件或权限；允许浏览器 `localStorage` 保存非秘密展示偏好，没有任意磁盘能力。画布只消费编译结果和源码映射，自己不解析结构。
- **主进程：** 打开库、读写文件、权限名单、索引、窗口。当前可信 `AgentHost` 和两项只读工具住在这里，性能迁移仍属工程选型；可执行第三方的安全隔离另有 [开放前置](topics.md#沙箱与任务授权)，不能由性能达标省略。
- **AgentHost：** 一场 `/` 的受控运行环境。愿景 / 选型 / 路线见 [施工对象](topics.md#agent-核心框架)。无工具最小环与一次性授权已验收；两项只读工具与来源核验已接入，其余工具未开。
- **尚未接线：** 通用资源代理、第三方执行隔离、MCP 客户端、AI 写类文件工具不在上图中。未来的数据流先在 [施工图](build.md) 排依赖并通过相应门禁，再更新这里的强制点。
- **正文编译：** 共享一条管线（零 DOM、零 CM6）。注册插件 → 解析 → 索引 → 把源码映射交给画布。人的索引、反链与任务工具复用解析能力及源码范围，不将人的全库索引作为模型任务数据入口。细则见 [已拍板决定](decisions.md)。

### 设备配置与展示状态

- `model-config.ts` 的兼容 v1／v2／v3 的 v4 内部连接 ID 绑定各供应商唯一凭据及模型清单；读取只返回非秘密字段与保存状态。模型配置校验、`safeStorage` 密文及原子保存由主进程负责，手动模型列表只在人的请求中读取候选。
- `assistant.json` 已保存设备级习惯，Host 启动取快照并拼系统提示，账本只记摘要。默认模型与助手习惯分别保存；助手页保存默认、底栏本篇临时选择及授权记录 ID 接线为本轮收口，是否已验看施工图对照表。凭据和模型快照不冻结权限。
- `TreeEntry.attachmentOf` 来自主进程的实际文件系统路径核验，`VaultState.navigationKey` 优先为设备库登记 id 的不可解释哈希；未登记回退同时绑定当前根身份与规范路径，仅用于本机展示偏好隔离，不是磁盘路径、对象版本或授权。附件子树只供人浏览；主进程的 `requireOrdinaryNotes` 核对获准对象原生祖先链及各父目录同级笔记，通过实际目录身份判断同名附件归属，覆盖路径别名。授权、读取前后与来源发送核验复用它；仅一次调用内共享枚举，不缓存跨调用结论，不按渲染层字符串授予范围，也不为每个增量递归扫描整库。核验期间无法读取或身份改变则拒绝；外部瞬间变化仍不是被原子锁住的文件系统，不能据此声称完整沙箱已交。证据见施工图对照表。
- 侧栏选中、展开、分区、附件与宽度由渲染层 `localStorage` 按 navigationKey 保存；不保存秘密、正文或权威权限，损坏回退不影响库记录。只有主进程可核验和执行文件、权限与 Host 操作。
- 外观主进程存储 `theme.json`；新增 `ChromeTextPreference` 的 tabs／sidebar 有限档位与原主题、reading 合并原子保存，不覆盖其他偏好。读取兼容旧记录，坏字段单独回退；配置默认只影响后续任务，字号不修改 Markdown 或根字号。

## 正文管线

```mermaid
flowchart LR
  Src[Markdown字符串]
  Pipe[共享编译]
  Idx[块与源码映射]
  View[CM6画布]
  Src --> Pipe --> Idx --> View
  View -->|"写盘=原文"| Src
```

- 结构只在这一条管线里解析。不要在画布、检索、Agent 里再各写一套。
- 语法扩展走插件，不改宿主。v0 插件含 GFM、frontmatter、公式、callout、wikilink、mermaid。callout 用 mdast 变换，不是第二套解析。
- 写盘永远是原文字符串。画布内部采用 LF 行结构，`view/source.ts` 保存原始换行并在编辑／源码偏移间映射；撤销、重做与身份操作不整篇归一化；原文历史 effect 仅映射替换落点，普通字符使用 CM6 自身历史，避免组合输入连续字符的失效范围。AI 边界断段先于预编辑建立，组合取消清理需匹配同篇代次，Enter／Esc 同时检查组合事件、229 键码和编辑器组合状态。`compile` 一次解析原文后复用树识别顶层独立 v1 账本锚点，只把正文节点交给呈现和索引；代码、引用、列表及 YAML 中的示例不构成边界。
- 新任务保存只写正文，主进程先保存可恢复回答，再核验正文回执、完成独立账本；不跨文件宣称原子事务。未迁移的旧尾部仍受原文保真边界保护，按篇迁移先保存并复读原字节，再按对象与修订移除尾部；正文围栏或 HTML 不能成为猜测旧账本字段的理由。
- 整库消失或根路径对象改变时暂停访问并关闭旧目录句柄，保留当前会话、核验快照及 tab，不能沿被搬走的旧句柄继续读内容。根路径 `dev/ino` 存活检查仅补充原生对象核验；原目录恢复后仍逐篇核对原对象，成功读回后恢复监听，换库前仍须处理保稿。

## 库内布局

2026-10-04 v4 包 A 接线：`readOpened` 只读正文及归属诊断，不迁移、发布或压缩；整文件修订绑定仍来自磁盘快照。`write` 只收正文，在同一库队列里复读并按对象／修订保留磁盘旧尾部，用既有分区及边界断言核对后替换。获准任务在实际库队列内重核有效 grant、来源权限前后快照、对象与整文件修订，旧归档写入后、正文原子替换前再次同步核验 grant 存活与权限原字节后才完成必要迁移；授权依赖的只读核验不回入该队列。Host 核对会话和前后对象／修订成功回执后续接 origin proof。任务与人的批次迁移均在原子替换前检查绑定容量，替换后立即登记对象连续性。新任务完成后才调度有界历史压缩。材料上界同时核验材料单元和独立任务序号、owner 归属与 registry 上界；坏登记不冒充序号零，拒绝复用序号，记忆管理仍显示本地内容和分类异常，清空／推进在提交队列内拒绝不可信上界。新任务容量门不套到完整旧原文。此处不代称后续恢复包已接线。


2026-10-05 v4 包 B 接线（受验代码 `bdf0ea2`，独立复核与整轮窗口门仍待总任务）：`lookupOwner`／历史上下文／摘要键只读，缺行但有描述不能冒充空历史。正常 registry 与 owner 矛盾拒绝自动选择；显式重建只复制原描述。普通归属发布使用现有 `.rgent-lifecycle` 的 `ledger-publication` 意图及两项控制文件回执，整库使用 `ledger-repair` 严格联合；未完成记录不当新归属权威。前后原字节、对象、根及权限都与意图匹配才续跑，不能靠更新时间或无记录的 owner 新值覆盖正常登记。

整库预览在同一库队列中绑定 session、原始完整树与权限，并复读前后快照；确认是人对新关联的授权。同根替换不继承；旧附件证明或完整锚点证明不足降为仅历史。附件使用二进制原始字节 SHA-256。恢复每批最多四个控制文件，每批及最终重新核验，重启不自动继续；日志记录预期版本及回执，来源续接只记元数据补丁，不复制来源文本。记忆逐条复用 `verifySource` 的分类／权限／依赖规则并要求唯一原文；条目与来源共同隔离核验结果，未知或不合格来源暂停。恢复不建立旧发送权限，主进程开始提交前清理单场许可和记忆预览。

设备 workspace 按登记 id 保存，读取仍检查当前规范路径与根身份。旧 workspace 仅在旧 path＋root 匹配时迁移；展示旧键仅由已核验旧登记提供，新登记不继承同路径残留偏好。恢复设置只消费现有 `ledgerRepair` 的严格动作和 frame／session 预览令牌；没有新增 IPC、页面、权限或对模型的附件读取能力。

2026-10-05 包 B 复核修补（`eacd3cb`）：`VaultSession.write` 在现有 mutation queue 中拒绝 `ledger-publication`／`ledger-repair` pending 或损坏日志下的正文替换。主进程恢复调用统一经 `VaultStructureGate.recover`：冻结窗口输入后，preview 真实保存并排空；commit 只接受无新草稿的原预览；resume 等待在途保存而保留脏 tab。全库写闸封闭后再次排空库队列，随后才读取预览／提交意图／续跑。本次扩展原 lifecycle flush 的严格阶段与 session／operation 令牌，resume 回执只表示护稿就绪，不冒充保存成功。恢复期间草稿仅在原 tab 内存中；失败不覆盖、不清日志，成功后保存原稿再离库。旧会话或旧操作释放不能解开新输入门，完整关闭协议仍属 E。

2026-10-05 包 B Host 待保存恢复修补：`VaultStructureGate.recover` 统一持有 Host 恢复门，建立时立即拒绝新启动与新补存，等待已登记补存和启动收敛后重核活动状态及当前会话。只有显式 resume 接受已结束任务的 pending；preview／commit 仍拒绝，避免重新关联旧回答。失败保留输出和 journal；续跑完整完成后先释放两门，再在当前 VaultSession、根与会话仍匹配时调用既有补存。恢复成功和补存失败分别处理，失败仍保留 pending；不新建 grant、不重派发模型。Host 的流式 checkpoint 与 `finishWrite` 均把根、原会话、有效对象及整文件修订传入现有内部 prepare 端口；生产与虚构评测入口明确转发该绑定。`VaultSession.ledgerPrepare` 在实际 mutation queue 内复用完整 `modelTierFor`（包括同对象别名保护），流式 checkpoint 另核实际 TaskGrant；所有等待结束后同步复核 grant 存活、会话、根、生命周期、权限原字节、对象连续性和正文修订，随后同步调用 `LedgerStore.prepare`。已结束任务补存不携带已撤销 grant，仍须通过当前权限与绑定；没有新授权或模型发送。后续正文继续沿用 CAS 和对象连续性校验。完整关闭／切库协议仍留 E。

workspace 的唯一性规则与寻址一致：有 id 行按 id 唯一，无 id 行仅在无 id 集合内按 path＋root 唯一；不同 id 可以保留同一物理根的历史行。旧无 id 迁移要求匹配旧登记及其已核验迁移证明，新登记、重新登记或新登记后的重定位不继承孤立旧行。成功写出的 workspace 可被同版本读回；无吞错、整文件删除或新身份授权。


- `.md` 就是笔记。
- 每篇笔记带一个附件夹，名字与笔记同名。图和 PDF 跟这篇走。引用写全路径，解析走 Markdown 标准相对路径。
- 权限名单和技能文件跟库走，对文件树隐藏。权限名单的选定路径见下方强制点。
- 2026-10-03 包 1：新任务账本由主进程 `LedgerStore` 写入 `.rgent/ledgers/<noteId>/<taskId>.json`；registry 与有限 owner 描述保存逻辑归属，正文不加 noteId。对象连续性无法核验时显示待核验，坏 registry 可通过显式入口从描述重建，但描述不代替对象与权限核验。旧尾部先精确复制、复读再移除，含糊章节只供回顾。
- 人搜、反链与模型工具只索引锚点之前的正文，不得索引账本。Host 组模型上下文时另行读取本篇账本，按 [产品合同 · 喂给模型](decisions.md#喂给模型) 的预算与来源规则处理。
- 密钥不进库。Host 阶段以 Electron `safeStorage` 加密，密文只存应用数据目录，解密材料由操作系统保护。
- 库根隐藏 `.rgent-lifecycle` 记录结构操作的身份、修订、权限迁移与恢复进度，不记录笔记正文，不提供历史版本。有效的未完成记录使 AI 访问失败关闭，直至按对象身份恢复；不由程序清空不可信状态。

## 库内文件生命周期

- 人的自动保存、Host 独立写回、权限修改、新建和结构操作由 `VaultSession` 的库内队列串行协调。结构提交开始先阻止本库新任务；无关任务仍在运行时拒绝新结构提交，受影响任务取消并保存输出后，画布再完成脏 tab 写盘。随后封住受影响路径的新写入，并在同一队列中重新核对预览后提交。冲突仍走现有双预览。失败时解除写入闸。
- 预览记录来源与目标、同名附件夹、对象身份、受影响目录、显式权限和全路径引用；提交重新核对，不接受过期预览。原生模块从固定库根核验路径，拒绝链接、重解析点、越界与覆盖；笔记 Markdown 字节在移动本身不变。
- `VaultSession` 为每次挂库生成会话令牌；结构操作等待 Host 和草稿期间、排队后及返回前均核对令牌。恢复完成事件与外部改动带会话归属，换库后的旧预览、旧恢复结果和迟到通知不能用于新库。
- 改名／移动的中断记录先落盘，再逐项搬迁。每项移动后复核目标对象身份；全部目标的类型与文件内容哈希核对通过后，才迁移权限和清除记录。人工确认的引用修复按每篇修订值进行；若修复对象也在移动范围内，记录修复后内容的哈希，以便原子替换改变文件身份后仍能核对并续跑；不记录正文。失败项须显式展示。未完成记录保持门禁关闭。macOS 的路径式原生改名在最后一次身份核对与系统调用之间仍可能受外部换名影响，不能把预检当原子证明；移动后复核用于防止静默报成功，不等于已证明对抗所有并发外部改动。
- 删除必须经 macOS 与 Windows 的系统废纸篓原位恢复和换路径竞态实测。仅接受能证明预览对象身份与原路径保持一致的调用，且须能核对恢复对象与原权限。现有 `shell.trashItem(path)` 接口单凭路径不满足这条证明；入口关闭，不能改用永久删除或库内改名暂存。
- 独立的 [macOS](../test/native/trash_mac.mm)／[Windows](../test/native/trash_win.cc) 废纸篓探针不编入产品，也不提供生产 IPC。`NSWorkspace.recycle` 的路径 URL、文件引用 URL及 `IFileOperation` 的 Shell 对象／删除前回调均已出现对象或库范围反例；Windows 拒绝删除共享的文件句柄同时阻止回收，父目录句柄仍不能封住子文件替换。当前没有可接线的安全删除实现；采证结果及原位恢复缺口见 [施工记录](build.md#9-月-30-日安全与恢复收口)。
- 移动前、每项移动后及完成前重新枚举源／目标子树，核对完整成员、类型、身份和字节；新增、缺失、替换或无法读取均保留恢复记录。隐藏子成员也属于对象集合，不能因文件树隐藏而漏核。合法旧版 v1 记录继续参与核验，损坏或缺乏可证明身份的记录不自动改写。
- `lifecycleStatus` 仅返回当前会话、记录字节修订号、操作和相对路径的逐项状态，以及有限失败码；不返回正文、原始隐藏记录或绝对磁盘路径。`lifecycleRetry` 绑定会话和记录修订，复用停止 Host、保住生成内容、保存草稿和封住结构写入的流程；状态浮层无绕过核验的入口。
- 结构门期间拒绝本库新任务；新提交若有无关活动任务则先拒绝，不主动取消。恢复已有记录时先停止流，并核对待保存任务路径与源、目标、附件及引用修复范围；相交则拒绝，不相交的输出原样留在 Host 内存。恢复核验成功并解除记录门禁后，才走原模型权限与修订值路径补存；失败保留输出，以独立字段说明，不能绕过权限或把它冒充未修复引用。

## 两套可见范围

- 人的搜索含禁止触碰。当前人搜是惰性全量 + 子串，可按压测换引擎。
- 模型检索先固定本场批准对象，再核身份、权限和内容并匹配／分页；不能调用人的全库搜索后过滤。解析与匹配能力可共用，缓存与读取范围不能串用；方法不与人搜子串绑定。
- 不要做成同一份「看不见」的索引。细则见 [已拍板决定](decisions.md)。

## 一场 `/` 的数据流

1. 人在空段段首按 `/` 输入；回车打开口令旁的授权浮层，显示固定参考对象及模型接收方；再次回车确认后发送并散场，把生成任务绑定到原笔记和落点。输入法组合期间不发送，取消保留口令。
2. 模型拿到三类带来源的内容：该笔记正文、按预算处理的本篇账本、这一次 `/` 落在哪两块之间。旧账本章节超限时可用本任务临时摘要，不改原文。
3. 回答先插回原笔记的未采纳块，接在 `/` 下面。切 tab 只结束输入交互，不取消任务，也不改变结果目标。
4. 人点采纳，才跟手写一个样。丢弃则删块。账本原文不动。
5. 后续工具须经 [统一授权与资源代理](topics.md#沙箱与任务授权)；受信任文件与网络服务在主进程核验执行，第三方代码须另经隔离。具体清单只见 [已拍板决定](decisions.md#工具)。当前范围授权约束 Host 和两项只读工具；执行隔离、其他工具和删除入口仍未开放。
6. Esc、停止按钮或关窗取消仍在运行的任务。未采纳块留在原笔记，并记中止原因。

## 沙箱边界的现状

文件基础与图片出口保持原门禁。`task-authorization.ts` 已提供仅内存、一次性消费的范围预览；授权绑定当前主 frame、库会话、命令、发起及参考对象、允许动作与模型／上限快照。目录固化为对象集合，提交及后续调用重验权限、身份和修订；只有受控成功写回续接发起篇身份。取消或结束撤销后续模型／读取调用，收尾只能向原篇保住已生成内容并遵守最新写盘门。通用网络代理和第三方隔离仍未接线，完成证据见施工图。

本节区分实际边界与未来规划，不给未接线能力添加强制点。

| 已有边界 | 代码证据与范围 |
|----------|----------------|
| renderer 隔离 | `src/main/index.ts` 的 `sandbox`、`contextIsolation` 与关闭 Node；preload 白名单及渲染层 CSP。保护界面进程，不约束主进程中的 Host。 |
| Host 与两项只读工具 | `src/main/index.ts` 注入单场授权、受控 `read`、独立 `write`、权限复核与单步模型流；`src/main/agent-host.ts` 校验并顺序执行读库／搜库，SDK 工具不配置 `execute`。主进程仍持有系统权限，没有可执行第三方沙箱。 |
| 文件与出口的现有边界 | 固定库根 `SecureVaultFs`、库内队列、会话及修订核验、秘密留主进程；模型文本与远程图片分别走既有通道。不能据此宣称未来工具已共用完整授权服务。 |
| 尚未成立的边界 | 用于搜索／MCP 的额外外部发送批准、统一工具资源代理、远端 MCP 和 OS 级本机第三方隔离及子进程限额均未接线。合同见 [沙箱与单场任务授权](decisions.md#沙箱与单场任务授权合同与开放边界)，方案与验收见 [施工对象](topics.md#沙箱与任务授权)。 |

现有删除安全门失败、文件替换残余竞态与中断恢复义务继续成立；未来进程隔离不能把这些缺口自动标成通过。规划目标图只放在施工对象，实际数据流仍以上方总览为准。

人的文件操作基础已按对应提交验收，单场授权已独立验收，当前只接读库／搜库；废纸篓删除与恢复核验已拆为独立未开能力，原生探针和失败证据不因此改变。默认范围与模型接收方已接入现有 Host；额外外部发送批准及远端只读 MCP 优先规则仍属未来合同，外部文件消失后的防重建和来源失效也须定向核验，不能以阶段名称代证。

## 2026-10-03 新记忆存储与使用接线

`WorkingMemoryStore` 只解析 v2 Markdown；条目按 UTF-8 长度读边界，内容中的机器示例不构成控制语法。正文与元数据单次原生 CAS 替换，控制区最低预留 256 KiB（不作为独立硬墙），全文件最多 2 MiB，不留旧代正文；文件损坏／外部替换保留诊断。`WorkingMemoryService` 分开证据、语义与许可：片段／任务字段、真实附件归属及权限本地复核；复核期到期不等于事实错误，账本清理不等于遗忘。生产 Host 只逐项复核已发送条目的版本与来源，无关写入不撤销任务；首次不可用降级为普通任务，实际使用后撤销仍停后续调用。库迁移不继承设备发送许可；记忆文件身份随库，未恢复永久 pin。

### 2026-10-03 新记忆强制点

`working-memory-store.ts` 的单文件 CAS 保留写入冲突检查；读侧只核本场条目和实际依赖。后台排队回执不改变材料，但人的条目更改会阻止晚到覆盖。持续约定容量不足只暂缓新项，释放后由服务重新核验来源再激活。遗忘移除已知派生正文，并保守清除设备摘要；水位及可替代的约束在一次替换里提交。明确诊断／重置预览绑定当前对象和字节修订，重置关闭许可并阻止此前材料自动重新学习。

## 单活动库与设备工作区

- `index.ts` 使用应用单实例锁和窗口复用；第二次启动只唤起原窗口。`VaultCatalog` 在应用数据目录维护 `vault-catalog.json` 和独立的 `vault-workspaces.json`，根路径采用原生规范路径与实际目录身份；登记拒绝父子库和别名重复。旧 `vault.json` 只在新目录文件尚不存在时用于一次启动兼容，不作为后续权威。
- `VaultSwitch` 协调只读目标检查、设置草稿、任务停止与保稿、后台整理停止、正文保存及队列排空。新绑定只在最后目标复核后通过 `openVerified` 提交；初始化诊断留在已提交的新库，不把旧目录信息覆盖到新会话。目录项保存失败不声称活动绑定已回滚。
- preload 与主进程共同核对库操作的会话信封；主进程用内置异步调用域固定请求归属，旧请求不能在等待后重新捕获新库令牌。任务取消、设备设置和后台图片等直接副作用另核原会话；该调用域不代替文件对象、修订或权限核验。响应返回和事件消费再次过滤会话。库图片 URL 带会话，旧 URL 返回失效，不按新库同名路径读取。授权预览与远程图片请求在提交时清理；后台回执也检查原会话。
- 渲染层工作区只保存 tab 顺序、选区、滚动及侧栏显示。恢复先读取各篇最新正文，再应用保存的位置；缺失篇保留不可核验提示，不重建文件。不保存正文草稿、撤销、任务许可或临时模型。浏览偏好继续沿用非权威 localStorage。
- 工作区恢复门在初次读取库状态前生效，覆盖目录初始化和全部 tab 恢复；实际交互、原生菜单及工作区保存共同受控，不能把空或部分恢复状态写回。恢复按调用代际和会话核对，旧恢复收尾不能释放新门；切换前的原库正文保稿仍走既有保存门。
- 库状态的可访问性与实际挂载绑定分开报告。根暂时失联时管理回执仍带原会话，取消选库不构成解绑；没有挂载才返回空绑定。preload 按主进程报告的绑定更新，原根恢复后可继续重新核验，真正切库后旧请求仍失效。
- 根身份是 `设备号:inode`。历史同 inode「切换即确认」实现已由 2026-10-06 包 3 退役：普通 `vaultOpen` 不改变根登记，`sameRootInode` 只作可能重新挂载的诊断。现有 `vaultCatalogChange` 的严格联合请求承载 root-preview／confirm／cancel；异对象重新定位也只返回预览，只有同对象纯移动沿原 relocation。
- `VaultCatalog` 的只读根预览绑定规范目标对象、原设备登记、工作区原字节修订、窗口/frame 与旧会话；120 秒、每窗口四份、单次使用。提交前及等待后原 frame 重新核验，关联只提供设备定位，不向账本／记忆批量换根或继承任务许可。目录提交成功但 attach 失败，旧实际会话仍在，当前失效根保留新的预览与选位置重试入口。
- 根恢复复用生命周期通道的 root-recovery-protect／recovery-release。保护回执列实际打开对象，只表示 draft held；取消计时器、同步全部正文、排空已发写入、停止旧任务并保留 pending。`VaultSession` 在既有 64MiB 与对象上限内保留独立 sourceSessionId 的最后核验快照，不加入新根 acceptsObject 或 successors。重复根恢复不得覆盖未解决的旧证明；最后显式舍弃清同路径版本，dispose 清内存证明。
- 根 attach 保留旧 tab 会话、对象和 availability，迟到事件与工作区不得覆稿；有旧 tab 期间不保存不完整工作区，逐篇处理后用既有恢复位置入口重新读取。稳定 catalog ID 工作区不改根字段；旧无 ID 只有唯一原登记匹配可补 ID，中断重试不重复改写；关键结构损坏的工作区保留并拒空写，正文仍可打开。
- 根保留稿的现有 noteSaveCopyPreview／Commit 仅扩 sourceSessionId：新根作目标，旧隔离证明作源，第二次人的确认只出版正文，核 body／basis hash、目标父对象、exclusive 写与 postread。保护分支不调用 recoveryCopy、importLegacy 或 memory rebind，不确认旧 pending；成功保留原 held tab 并开新正文 tab，原对象仍有明确舍弃出口。普通单篇另存语义保持。
