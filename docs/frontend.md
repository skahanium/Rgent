# 前端协议

本文记录已经与用户确认的 Rgent 前端设计规则，供后续界面施工与日常调整使用。它约束**呈现方式**；笔记、AI、权限、搜索和保存的产品行为仍以 [已拍板决定](decisions.md) 为准。本文与产品合同冲突时，先按产品合同处理并修正文档。参考图表达整体观感，文字规则优先于图片细节。界面视觉遗留项见 [施工图](build.md#界面改造已交用户视觉确认完成)；前端冻结已按用户 2026-09-30 的样张确认解除（范围见该节记录），设置其余子页与图谱仍未开放。

## 设计语言

Rgent 是以写作和查阅为中心的工作区。画布安静，导航清楚，控件精致而可辨；科技感来自准确的层级、状态反馈与流畅操作，不靠霓虹、重阴影或成片装饰。参考 HanaAgent 等作品的整体协调感，但不照搬其布局、插画、品牌或主题名称。

- **日间：** 冷白画布、浅灰层次、同为浅色的侧栏；蓝紫色作优雅而克制的交互点缀。普通正文呈中性黑，不用绿色或蓝紫色染普通段落。
- **夜间：** 深蓝灰的“夜间档案”方向。画布、侧栏、浮层、文字、边界和点缀一起调整，保证久读舒适；不是把日间颜色逐项反相。
- **辨识符：** 当前落点使用短而清楚的“页边索引”细线，在树的当前项、编辑区位置提示、设置选中项等需要定位的地方沿用同一逻辑。它是状态标识，不铺满所有行。
- **字体：** 默认长篇正文用适合阅读的衬线字体、Markdown 标题用无衬线字体；用户可在设置中分别为正文和标题选精选的衬线或无衬线方案，两者可交叉搭配。导航、tab、控件和状态文字始终使用界面字体，不随阅读偏好改变。字重、字宽、行距需分别照顾中英文和长文。
- **形状与层级：** tab 和小控件保留柔和圆角；画布、侧栏与浮层靠轻微明度差、细边界和节制阴影分层。圆角和悬浮不应把笔记正文切成一组卡片。
- **控件细节：** 使用已选定的“清晰轮廓”方向。同类图标使用一致的尺寸、线重与对齐网格。图标本身可以小，实际可点区域须足够清楚；默认、悬停、按下、选中、聚焦和禁用状态采用同一套反馈逻辑，不让用户猜控件能否操作。
- **动效：** 采用已选定的“轻快克制”节奏，用短促、稳定的颜色、透明度或小幅位置变化表示状态；输入、滚动、切 tab 时不跳动布局，内容切换不等一段退场动画才响应。不做持续闪烁或大面积光效。系统要求减少动态效果时停止非必要过渡。

### 语义 token

实现时先以语义角色组织日夜两套值，再为组件引用角色，不在各处散写同一色值。最低限度应区分：`surface.canvas/nav/overlay`、`text.body/heading/muted/onAccent`、`accent.primary/soft/focus`、`border.subtle/strong`、`state.hover/selected/disabled`、`ai.prompt/answer`、`status.online/offline/error`，以及字体、间距、圆角、阴影和动效时长的相应角色。提问比回答有更强的视觉权重，回答使用更柔和的同系伴随色；日间可表现为深浅差，夜间按对比度调整，不机械压暗提问。两者与普通正文一眼可辨，同时仍像文章内容。联网状态的蓝色光晕是状态色，不强迫所有交互都变蓝。

这些**角色和相互关系已定**；具体 hex、字体文件、宽度、间距、圆角和毫秒数在实现与双主题检验中调整。装饰性分隔线可用 `border.subtle`，需要靠轮廓辨认的输入框和按钮用满足对比度要求的 `border.strong`。调整必须保持阅读层级、辨识度和可访问性，不得把数值临时稿提升成永久产品数字。

## 工作区

### 顶栏与侧栏

- 顶栏是多篇笔记的 tab 栏，沿用柔和圆角、当前项浅点缀底色、其他项安静退后的形式；文件图标与标题帮助辨认当前篇。tab 文字与原生窗口控制件在视觉上垂直居中。不得用单个文档路径替换 tab，也不在顶栏放 `rgent` 文字标识或账本入口。
- 左侧文件树相对早期稿收窄；日间保持浅色。它仍可收起且默认收起，打开时不要挤坏正文和右侧反链。文件夹、Markdown、PDF、图片和其它文件须有可辨的类型图标。文件夹**平时显示文件夹图标**，鼠标悬停或键盘聚焦时，同一图标位置变为展开／折叠按钮，不在旁边额外添一枚箭头；图标位置始终是可点击的折叠目标，无悬停设备可直接点它。
- 设置入口固定在左侧边栏底部，独立于文件树滚动；展开时显示图标与「设置」，收起时保留可点击、可键盘聚焦的图标入口。
- `搜索笔记`是保留现有圆角轮廓的按钮，文字旁显示平台快捷键，不放放大镜符号。⌘K／Ctrl+K 打开带搜索框与结果的悬浮页；⌘F／Ctrl+F 留给当前笔记的篇内查找。结果内容与人的全量可见范围按 [检索合同](decisions.md#检索与联网)，不由视觉稿决定排序或片段算法。

### 编辑画布与辅助信息

- 画布保持宽裕留白和清楚的文字宽度。宽窗正文适度拓宽，普通段落在阅读与编辑时一致地两端对齐，末行自然结束；标题、代码、表格和结构性列表保持各自的排版。普通正文承担阅读主角；工具、元信息和操作控件保持次要层级。日间普通正文为中性黑，夜间为舒适的浅色。
- 当前笔记的账本入口始终显示在正文画布右上角，滚动时不消失。账本在同一 tab 内临时只读显示；关闭后恢复正文的光标与滚动位置，不改草稿或文件内容。
- 提交后的 AI 提问留在正文，视觉上以较粗字重和前缀 `>` 标识，**不显示触发时的 `/`**。`>` 是由口令身份产生的显示前缀，不能为了画出它而把口令改写成 Markdown 引用；落盘内容和身份仍按 [记录即正文](decisions.md#记录即正文) 的规则。AI 回答向内缩进一个字宽。两者的颜色跟随主题，以不同强度的同系点缀作轻微区分；不使用独立底色卡片、粗边框或固定绿色。回答的“采纳”“丢弃”直接可见，其他操作收进“更多”，控件不压过文字。
- 编辑器／阅读器的右缘有悬浮标题索引，只取正文的一级、二级、三级标题。短线组位于画布可视区纵向中段；通常逐条显示紧凑的短横线，右对齐，一级最长、三级最短，不用一整块背景包住全组。可见短线的间距以早期过疏稿的**约 40%**为基准，命中区可以比短线大，不能因视觉紧凑而难以操作。悬停或键盘聚焦仅显示对应标题，激活后跳到对应标题；当前阅读位置有清楚的状态。索引属于画布边缘，不取代右侧反链栏。
- 独占源码行的图片按自身尺寸呈现，上限为正文宽度；图片位于行首而后面紧接正文或 Markdown 标题时，阅读态也把图片、正文或标题分开呈现，标题进入正常层级和页边索引，笔记原文不因此改写。句中的行内图片仍保持小尺寸，不把相邻文字挤到旁边。外链图片加载失败时显示简洁的说明与重试，不在阅读画面铺开长 URL；人的／已采纳正文 HTTPS 自动加载，未采纳 AI 正文、全部账本与 HTTP 图片逐张点击加载。点击前可查看地址和来源，详见 [编辑与渲染合同](decisions.md#编辑与渲染)。
- 右侧反链仍常驻，并按文件夹组织。底栏与上方用一条细线分开：左侧行列与字数，**中间是模型模块**（原生下拉，按连接分组列出已配置模型，切换即改变新任务所用模型；无可用模型时显示「未配置模型」与打开设置的引导，不放死控件），右侧联网圆点与库名。已提交的生成任务运行时，单任务显示**来源笔记、任务状态与停止入口**；多任务显示数量，并能从小浮层逐项查看和停止。切到别的 tab 后仍指明原笔记，且不挤掉既有项目。联网总闸是一个可点击、可键盘操作的小圆点：离线灰色，联网时蓝色光晕；不常驻“联网／离线”文字，状态通过悬停提示和无障碍名称说明。Agent 联网功能未开放时只如实显示离线状态。

### 浮层与特殊状态

- 本轮仅新增 `/` 口令旁授权浮层：用现有主题、控件和焦点语言呈现发起篇、参考范围、实际接收的模型与主机及发送说明（模型选择在底栏，浮层只如实显示本场实际接收方）；回车确认，Shift＋回车换行，输入法组合不提交。预览变动重新确认，取消保留口令，不占用冲突决策浮层。工具运行状态与来源回顾复用既有底栏和同篇账本：显示模型步骤、读库／搜库及停止入口，账本区分实际读取来源与模型消息引用来源，并按发生顺序呈现过程（模型步、工具调用与结果、检索词、失败与收尾）与模型推理；正文只出现回答，工具原文与思维链都不进正文；不重开整体视觉。写入失败的生成内容留作待保存：底栏提示写明原因与下一步，人在该篇修好语法并成功保存后自动补存一次；仍未落盘时关窗流程仍提供明确放弃。

- 设置主页及各级子页使用同一套字体、色彩、选中态、边界和控件语言。设置面板**悬浮在正常工作区上方，面积比正常面板小**，但有足够空间容纳真实样张；在最小窗口内留外边距并在面板内部滚动。打开时正文、侧栏和反链明显柔焦并适度压暗，面板保持清晰。面板没有独立顶栏、横向顶栏分隔线或右上角关闭按钮；“设置”是侧栏标题，点击面板外或按 Esc 关闭，面板内点击不关闭。导航按工作对象分组，可用页面配同风格细线图标；未开放页面不出现。将来的助手、记忆、供应商管理等导航，只随各自数据边界和可用能力开放，名称、控件与排布须届时核对，不从参考截图提前锁定。能力范围见 [产品合同](decisions.md#设置里有什么)。
- 已开放「界面」页的日间／夜间／跟随系统三选项；主题卡展示能辨认侧栏、标题和正文的微缩工作区，并在下面提供更大的中英文静态笔记样张。「界面」页另提供正文和标题的独立字体选择、正文字号、行距和最大阅读宽度；调节只即时更新面板样张，确认保存后才影响编辑阅读区、AI 正文与同篇只读账本，关闭未保存的调节则放弃。默认保持此前的衬线正文、无衬线标题和现有尺寸。模型、运行页沿用同一面板语言，不显示不能使用的其他子页。模型页按单列分区：连接卡片列表（每张两行：供应商名与「密钥已保存／未保存 · N 个模型」，下面是端点主机；选中卡左侧有强调条，另有一行「供应商 + 添加连接」）→ 编辑连接（接口地址、替换密钥、保存／删除，删除为两段确认）→「读取模型」（页内展开候选，非悬浮层）→ 该连接的模型清单（每行模型 ID 与可就地编辑的上下文容量、移除，末行是「模型 ID + 上下文 + 添加模型」）。页面不设「当前模型」按钮；用哪个模型在底栏选。空态写明下一步，错误用同一处 alert 区呈现。接口地址是唯一真源，已知端点只作该字段的候选（同一控件对所有供应商生效，不为单一厂商加控件）；密钥只显示保存状态，绝不回显。「读取模型」由人点击后只对当前连接发一次只读请求，结果只作候选、勾选后才写入，端点未提供上下文容量时要求人填并写明原因。运行页编辑三档有限上限。偏好按设备保存；跟随系统时响应系统变化。主题切换须同时作用于画布、侧栏、反链、浮层和原生窗口外观。
- 搜索是独立于文件树按钮的悬浮页。弹出后聚焦输入框，Esc 可关闭；键盘能访问结果并返回原工作区。空查询内容、排序和结果片段不从静态图推导，沿用既有检索合同并在界面施工时核对。
- 窗口稿与磁盘稿冲突时，决策界面同时给出**并排的两份可阅读预览**：显示相同的前后文，分别强调发生变化的文字；“听窗口”“听磁盘”放在对应预览下方，并写明各自会舍弃哪份修改。不能只靠颜色表达差异。退出保存失败的重试、继续编辑、明确放弃，以及选库、库丢失和错误状态，也沿用这套视觉语言，操作结果以产品合同为准。
- 未来任务授权与扩展预览沿用现有浮层语言，分别让人辨认读取范围及选定模型接收方、结构动作的对象／目标／附件／影响，以及外部请求的实际内容／目的地／用途；读取不隐含向搜索或 MCP 发送。范围内连续执行仍提示失败或陈旧状态，删除另逐次确认。本轮已交付 `/` 口令旁授权浮层与工具状态／来源回顾；扩展授权与结构、外发用途预览的控件、入口和布局仍待各自阶段核对，设置页不新增，也不提供解除限制的开关；行为见 [沙箱合同](decisions.md#沙箱与单场任务授权合同与开放边界)。

## 可访问性与验收

- 日夜主题都按 [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/) 检查：普通文本至少 4.5:1，大字至少 3:1；有意义的控件边界、图标和焦点指示至少 3:1。浅灰辅助文字与细线不能因“轻”而失去可读性。
- 选中、禁用、错误、权限和联网等状态不能仅靠色相区分；键盘焦点可见，文件夹切换、tab、搜索、标题索引、设置与冲突决策均能用键盘完成。悬停才出现的操作需有聚焦及无悬停设备的等价入口。
- 悬浮搜索、设置和模态决策打开时，焦点进入浮层；关闭后回到合理的触发位置。模态决策期间键盘焦点不能落到底层工作区；放弃修改、删除等破坏性选项不能成为默认操作。
- 验收至少覆盖当前支持的最小窗口 `800×560`、常用窗口 `1200×800`，以及日夜、长文、多 tab、长文件名、搜索与设置浮层、冲突双预览、减少动态效果。现有右反链与正文不能因窗口变窄而无声消失；更窄窗口的新布局另行讨论。
