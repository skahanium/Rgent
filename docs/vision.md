# 理念与远期

## 这是什么

Rgent 是 **AI 原生的单机笔记软件兼个人资料库**。Markdown 文件是唯一产品真相。AI 是写在文档里的能力，不是旁边另开的通用 Agent。

它不是网页多租户服务，也不是「圈一块工作区、另开会话区让模型干活」的通用 Agent 驾驶舱。用户打开的是自己磁盘上的一个文件夹：一篇笔记一个 `.md`。可以像普通 Markdown 软件一样顺畅写作，也可以在同一页里用快捷键做润色、扩写、缩写或问答。和 AI 的来往仍是这份 Markdown，没有第二套会话格式。

## 理念

- **文档是根。** 先做坚实的语法体系与高水平渲染/写作。聊天窗不是产品正门。编辑器里的真相是 Markdown 字符串（CodeMirror 6 即时渲染），不是另一份富文本树。
- **一次任务靠 Harness，不靠通宵外循环。** 页内 AI 要有目标、工具、观察、刹车和可核对的完成；人离开后自动扫库改笔记不是 v0。
- **笔记与对话没有类型分界。** 一篇可以是纯手写、问答记录、或二者缠在一起。可以选中一段当正文改写，也可以在同一页往下问。用户能把对话收成成稿，也能把成稿接着聊。磁盘上不搞两套扩展名或两套库。
- **成稿给人看，对话可藏。** 换 Typora / Obsidian / VS Code 打开时，主要看到正文。问答写在同一文件的约定区块里（注释、frontmatter 或专用围栏），不抢版面。应用里仍是同一页。
- **AI 是文档操作器，不是万能助手。** 只在许可路径里检索、读写笔记；没有 Shell，没有独立会话数据库。当前打开的 md（含幕后区块）就是记忆。
- **约束在工具层，不在提示词。** 模型不可信。禁止触碰的路径不进索引、工具直接拒绝。「必须遵循」的原文只读检索与引用，改法规/手册只能用户动手。规则跟着库走，由应用执行。
- **库就是普通文件夹。** Finder、Git、别的编辑器碰到的就是同一批文件。应用不当第二份主存储。

## 远期目标

做成可安装的成熟 macOS 与 Windows 客户端：打开自选库即可写作；C 类 Markdown 渲染站得住；页内 AI 能在许可目录里比较自如地建/改/挪笔记；本地三档检索与联网搜索可用；prompt-only skills 可配。安装包签名与商店分发以后再跨。

## 非目标

施工时不要当成默认能力往上堆：

- 通用电脑 Agent、独立 Agent 会话区、整包编码 Agent（如 Harness `Coder()`）
- 账号体系、笔记默认云同步、多租户后端、把网页当正门
- Python / Pydantic AI 边车（第一版纯 TypeScript）
- 第一版向量检索、多库同时打开、打进 Playwright 第二份浏览器、无人值守外循环扫库改笔记
- Linux / 移动端承诺
- 用 Shell 或任意脚本绕过文件工具与 ACL
